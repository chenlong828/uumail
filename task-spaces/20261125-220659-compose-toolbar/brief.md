# W-M3-21 撰写页顶栏：发送置顶、关闭问存草稿

## 背景

用户反馈（2026-11-25，附 macOS「邮件」撰写窗口截图）：撰写页的「取消 / 存草稿 / 发送」分在底部左右两段，不符合 macOS 语言。「macOS 的设计语言很简单：关闭的时候会问是否要保存草稿箱，红色按钮默认就是取消，然后准备一个大大的蓝色发送按钮就 OK 了。」确认口径：

- 顶栏左侧红色关闭按钮，标题居中，右上只有一个大的蓝色「发送」；
- 关闭（红点/Esc）时有改动 → 询问是否存草稿：存草稿 / 放弃 / 继续编辑，默认「继续编辑」（Esc，安全优先）；
- 底部操作条与旧右上 `xmark` 去掉，不再保留第二个关闭入口。

## 范围

- 改：`Sources/uumail/ComposeView.swift`（顶栏、状态行、关闭确认）。
- 不改：sheet 宽高计算、收件人表单与候选浮层、格式栏、`ComposeEditor`/`ComposeDocument`、`ComposeViewModel`/`ComposeScene`/`Outbox`/schema/依赖/target；字号基线规则（100% 字符串标题、>100% 显式缩放 label）不变；发送只入队、`hasEdits`、`canSend` 语义不变。
- 回归：`SCN-0016` 的取消/确认与等宽断言、`SCN-0015` 的五档字号基线、`SCN-0017` 的候选浮层位置（顶栏高度变化不影响表单/浮层锚点）。

## 验收标准

1. 撰写 sheet 顶栏一行：左侧红色关闭、标题居中、右上「发送」；发送为 `borderedProminent` 大按钮、默认按钮（Return）。
2. 底部无操作条；右上无单独 `xmark`；Esc 等价关闭；有改动时弹「存储草稿？」，含「存草稿 / 放弃 / 继续编辑」，Esc 落到「继续编辑」。
3. 480pt 宽度与 100%/145%/175%/225% 五档字号下，标题与两枚控件不重叠、不截断到不可读；发送的 `canSend`/发送中禁用不变。
4. 状态文本（正在发送/已加入发件箱/草稿已保存/失败原因）在顶栏下方单独一行可见，编辑态零高度，不挤压顶栏。
5. 发送/存草稿/放弃的数据语义不变（只入队、草稿不入队、失败保留内容）；全量测试与架构门不退化。

## 未决

- 红色关闭点是 sheet 内的自绘控件（系统红绿灯只在独立窗口上）；若要真红绿灯，需把撰写改成独立 `NSWindow`，另立增量。
- 不做 Cmd+S 存草稿与发送失败横幅。
