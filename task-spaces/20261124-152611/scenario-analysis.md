## 2. 拆卡理由

三张卡，各自对应一个可独立交付的结果：

| 卡 | 动作 | 依赖 |
|---|---|---|
| `REQ-0031` | 列表双击 → 浮动阅读窗（回复工具栏、就地撰写、默认显示图片、打开即已读） | 无 |
| `REQ-0032` | 日历单击选中 / 双击 → 同一浮窗显示邀请邮件（工具栏：转发 + 在日历中打开） | 浮窗本体（`REQ-0031`） |
| `REQ-0033` | 列表默认显示最近 30 天（不封顶） | 无（与 `REQ-0031` 共用按引用读取，但互不阻塞） |

不并卡：`REQ-0032` 的验收核心是「取一封不在当前列表页的邮件」与日历交互替换；`REQ-0033` 是全局列表行为变更，动到同步/性能/既有场景。任何一项延期不应把另外两项一起卡在 `accepted`。

## 5. 场景草案（供 `T-1124-16` 落卡）

### 5.1 `SCN-0025` 浮动阅读窗（新）

**结果**：用户在列表里双击（或选中后按 Enter/空格）一封邮件，得到一个可移动的阅读浮窗（宽默认等于阅读区、高默认等于主窗口 85%，记住用户调整），里面是这封信封头、只读会议卡与正文，图片默认显示并有一行外部来源提示；工具栏「回复/全部回复/转发」把浮窗就地切成撰写；打开即标已读。同一时刻只有一个浮窗，撰写中双击另一封不替换。

**入口（草案）**：
- `CMP-APP#MailboxView`（行双击/Enter/空格、浮窗场景、工具栏、远程提示）
- `CMP-PRES#ReaderViewModel`（按 ref 读取、信封头/会议卡/正文、即读、回复种子）
- `CMP-PRES#ReaderRouter`（单例路由：当前 ref、替换/拒绝/置前）
- `CMP-SCN-READ#message(_:)`、`CMP-SCN-READ#messages(folderID:since:)`（D12，待设计定名）

**运行序（草案）**：
1. 双击/Enter/空格 → 视图把 `MessageRef`（folder + serverID）交给单例路由；主窗口选中态不变。
2. 路由置当前 ref：窗未创建 → 按「阅读区宽 × 主窗口高 85%（480/460 下限、屏高上限）」创建并置前；已存在 → 替换并置前；撰写态 → 拒绝替换，置前 + 提示。
3. `ReaderViewModel` 按 ref 取邮件；取不到 → 窗内中文「找不到这封邮件」。
4. 渲染信封头 + 会议卡（只读）+ 正文（缓存优先；未缓存占位 + `ReadScene.open(ref)` 补拉）；浮窗 `allowsRemoteContent = true` + 顶部静态提示。
5. 打开时标已读：本地落库（失败给中文提示）→ 服务器尽力回写（失败静默）。
6. 工具栏「回复/全部回复/转发」→ 用本窗消息与可引用正文构造 `ComposeViewModel`，内容区切撰写（编辑器仍阻止远程资源）。
7. 取消/发送/存草稿 → 回阅读态；撰写态关闭 → 「放弃这封邮件？」确认。

**失败路径（草案）**：ref 不存在 → 中文提示 + 关闭；正文补拉失败 → 占位 + 重试；本地标已读失败 → 中文提示（不阻断阅读）；回写失败 → 静默（沿用 `SCN-0013`）；撰写种子失败（无发件人）→ 与主窗口同文案。

**不可变引用（草案）**：`SCN-0004`（读取与渲染）、`SCN-0012`（信封头）、`SCN-0023`（会议卡）、`SCN-0016`/`SCN-0021`（撰写视图）、`SCN-0006`/`SCN-0007`（回复种子）、`SCN-0013`（主窗口远程策略）、schema 与 target 不变。

**测试草案（3 正 1 反）**：

| ID | 类型 | 断言 |
|---|---|---|
| `T-SCN-0025-01` | 正 | 双击 / Enter / 空格 → 浮窗出现，标题/信封头/正文 = 该封；主窗口 `selectedListKey` 不变；宽度 = 阅读区宽、高度 = 主窗口高 × 85%（含 480/460 钳制与屏高封顶）；用户调整后再次打开沿用记住值 |
| `T-SCN-0025-02` | 正 | 「回复」→ 撰写态收件人 = 原发件人、主题 =「回复：…」、引文 = 当前正文；取消 → 回阅读态、outbox 无新行；「转发/全部回复」种子与主窗口一致 |
| `T-SCN-0025-03` | 正 | 打开浮窗 → 该封本地变已读且主窗口列表刷新为已读；回写被调用一次；浮窗阅读态 `allowsRemoteContent = true` 且提示存在；渲染文本含远程图片标记（CSP `img-src` 放行） |
| `T-SCN-0025-04` | 反 | 撰写态双击另一封 → 内容不变 + 提示文案；撰写态关闭 → 「放弃这封邮件？」取消 → 仍在撰写、outbox 无行；确认 → 窗关闭且不入队；整个过程主窗口可切换选中、列表不受影响 |

### 5.2 `SCN-0024` 增量（日历入口）

在现有「运行序」第 8 步与测试表上**替换**详情相关段落：

- 运行序第 8 步改写：单击事件块 → **选中高亮**（不弹窗）；双击 / Enter / 空格 → 浮动阅读窗显示来源邮件；浮窗工具栏「转发」「在日历中打开」；日历入口不带回复。
- 替换/新增断言：
  - 单击月/周事件块 → 该块选中高亮，且**没有** sheet 出现。
  - 双击月视图事件块 → 浮窗显示来源邀请邮件；主窗口仍停在日历（侧栏选中不变）；周视图同样。
  - Enter / 空格 对选中事件块与双击等价。
  - 浮窗工具栏恰为「转发」「在日历中打开」；转发就地进撰写；在日历中打开沿用 `SCN-0023` 的 `.ics` 行为。
  - 浮窗内会议卡无按钮。
  - 来源邮件被删/不在库 → 中文「找不到这封邀请邮件」，工具栏导出仍可用。
- 删除断言：「点事件块 → 360×240 详情」与「详情『打开邮件』→ 跳回邮件页」；在场景卡写清这是 `REQ-0032` 的显式替换，不是回归。

### 5.3 `SCN-0026` 列表窗口（新）

**结果**：选中任一文件夹，列表显示该文件夹最近 30 天的全部邮件（不按条数截断），状态栏计数为真实条数；30 天前的邮件不在列表；5k 规模下加载不退化。

**入口（草案）**：`CMP-APP#MailboxView`（列表与状态栏）、`CMP-PRES#MailboxViewModel`（加载窗口、计数）、`CMP-SCN-READ#messages(folderID:since:)`、`CMP-STORE#messages(account:folder:since:)`。

**运行序（草案）**：
1. 选文件夹 / 刷新 → `MailboxViewModel` 以「now − 30 天（本地自然日 00:00）」向 `ReadScene` 取该文件夹邮件，按 `received` 倒序。
2. 结果一次性替换 `messages`；状态栏显示实际条数。
3. 切换文件夹、同步、删除、已读均沿用既有路径；窗口外邮件不进入列表。
4. 失败 → 中文错误 + 重试，不清空已有列表。

**测试草案（3 正 1 反）**：

| ID | 类型 | 断言 |
|---|---|---|
| `T-SCN-0026-01` | 正 | 夹具含 250 封 30 天内 + 50 封 30 天前 → 列表恰 250 行（不再是 200），倒序，计数 250 |
| `T-SCN-0026-02` | 正 | 夹具含 1,100 封 30 天内 → 全部载入、计数 1,100、无「仅显示前 N」文案 |
| `T-SCN-0026-03` | 正 | 5,000 封夹具下加载 < 1s（M4 基线阈值），列表滚动/选中不卡；切文件夹后计数正确 |
| `T-SCN-0026-04` | 反 | 空文件夹 / 同步中 / 读库失败 → 空态与错误文案与现状一致，失败可重试且不清空已有列表 |

## 7. 风险（已登记到 `plan/risks.md`）

- **R62** 不确认就扩读契约 → 实现绕过场景层（**已由 D12 的 P1 确认关闭入口**，仍按任务门执行）。
- **R63** 第二窗口的默认尺寸 / 单例复用 / 无头可测性未验证 → 探针先行，过不了换 AppKit。
- **R64** 浮窗撰写与主窗口撰写同一封回复并存 → 两份草稿 / 引文错位 / 关闭丢稿。
- **R65** 日历更早邀请的正文未缓存 → 占位 + 补拉失败观感空窗。
- **R66** 浮窗默认加载远程图片 → 追踪像素泄露打开行为；同封邮件两窗口表现不一致。
- **R67** 列表 30 天不封顶 → 大邮箱首屏读取/渲染变重，可能突破 5k 基线。
- **R68** 日历去掉详情后单击/双击/键盘与选中态手势冲突 → 双击当两次单击、选中不生效。
- **R69** 打开浮窗即标已读 → 误双击即已读，不可撤销。
