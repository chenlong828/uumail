# REQ-0032 日历双击直接打开邀请邮件

- **ID**：REQ-0032
- **类型**：`feature`
- **场景叙述**：用户在日历页**月视图或周视图**里单击一个会议块，该块**选中高亮**（不再弹 360×240 详情）；**双击、Enter 或空格**弹出与 `REQ-0031` 同一形态的浮动阅读窗，窗里显示这场会议的**来源邀请邮件**（信封头、只读会议卡、正文，远程图片默认显示）；浮窗工具栏只有两个动作：「转发」（把邀请转给别人）与「在日历中打开」（`.ics` 导出给系统日历）。不必先看详情，也不必把主窗口切回邮件页。
- **价值**：不做的后果——现在必须「点会议块 → 360×240 详情 → 点打开邮件 → 主窗口切回邮件页」，三步且日历上下文丢失；日历里更早的邀请（不在当前列表页）只能靠手动搜索。想转发一场会议给别人，目前只能先找回那封邀请邮件再转发。详情那个小窗只显示摘要，看不到邀请正文里真正要读的内容。
- **非目标**：
  - 不接受 / 拒绝邀请，不写 Exchange 日历，不改日历同步范围与「不回填历史邀请」的既定代价。
  - 日历入口**不提供回复 / 全部回复**（工具栏只有转发与在日历中打开）；回复仍走邮件列表入口。
  - 不做拖动改期、不在日历里改会议、不做提醒 / 通知 / 日视图 / 年视图、不新增日历右键菜单。
  - 不改月 / 周网格布局与投影规则，不改 `.ics` 序列化内容，不改「在日历中打开」的系统日历导入路径。
  - 不改 schema、不新增 target、不新增第三方依赖。
- **约束**：
  - **单击 = 选中**：会议块（月视图事件块、周视图事件块）单击只做选中并给可见高亮，**不再弹任何详情 sheet**；同一时刻只有一个选中事件。
  - **打开入口**：双击、Enter、空格三者等价，都对当前选中会议块生效；打开后**不改侧栏选中**、**不切回邮件页**（主窗口停在日历）。
  - **复用浮窗**：与 `REQ-0031` 同一个单例窗口、同一套默认尺寸与记忆口径（宽 = 阅读区宽度、高 = 主窗口高度 85%、同样上下限与跨启动记忆）。
  - **工具栏**：日历入口的浮窗工具栏 = 「转发」+「在日历中打开」（代替原详情里的导出按钮）；转发就地切换为撰写，行为与列表入口的转发一致；「在日历中打开」行为与 `REQ-0023` 的会议卡导出一致（重复会议导出整个系列、失败给中文文案）。
  - **会议卡只读**：浮窗内会议卡不开放按钮（导出已在工具栏，避免同一窗两个同名按钮）。
  - **来源邮件可不在当前列表页**：日历展示库里全部已收邀请，而列表只加载当前文件夹；浮窗须按「文件夹 + serverID」从本地库直接取这封邮件（同批新增的按引用读取面，口径见决策 D12），不依赖列表当前页、搜索词或选中项。
  - **取不到时**：邮件已被删除或从未入库 → 浮窗内显示中文文案「找不到这封邀请邮件」，不空白、不崩、不留半透明空窗；工具栏的「在日历中打开」仍可用（它只依赖会议行）。
  - **零网络**：打开浮窗与阅读区同一条路径（缓存优先、未缓存先占位后补拉），补拉失败给占位与重试。
  - 远程图片在日历入口浮窗同样默认显示，顶部同样有静态提示（口径同 `REQ-0031`）。
- **影响场景**：
  - **修改 `SCN-0024`（`calendar/browse/calendar-grid`）**：**替换**「点事件块 → 360×240 详情 → 打开邮件跳回邮件页」这条断言，改为「单击选中高亮」「双击 / Enter / 空格 → 浮窗显示来源邮件」「浮窗工具栏 = 转发 + 在日历中打开」「会议卡无按钮」「来源邮件已被删 → 中文错误」「远程图片默认显示」；场景由 `verified` 转 `designed`，重新验证后回 `verified`（状态翻转让设计任务执行）。**去掉详情 sheet 是本批对 `REQ-0029` 已交付行为的显式修改**，须在场景卡写清替换关系，不留两套口径。
  - 新建 `SCN-0025`（`REQ-0031`）：浮窗本体；本卡只作依赖引用，不重复认领其断言。
  - 回归（不新增断言）：`SCN-0023`（会议卡与 `.ics` 导出在阅读区不退化）、`SCN-0012` / `SCN-0004`（阅读内容）。
