# REQ-0024 远程图片放行后的实际加载

- **ID**：REQ-0024
- **类型**：quality
- **场景叙述**：用户打开一封含远程图片的 HTML 邮件，阅读区默认阻止图片；用户点击「加载远程图片」开启放行，期望**当前这封邮件里的远程图片实际显示出来**，而不是只切换了一个看不见的 CSP 档位。用户样本邮件（行程提醒类）正文 4 个 `<img>`：3 张可见 logo/横幅 + 1 张 1×1 跟踪像素，全部以明文 `http://` 提供；开启后图片区仍然空白，无论点几次开关都一样。不开启/关闭后仍应阻止图片请求；放行只作用于当前邮件，切换邮件或重开窗口回到阻止。
- **价值**：用户点「加载远程图片」的直接目的就是看到内容。开关状态变了、图片永远空白，等于功能不可用：行程单/订单/对账单/营销邮件里的行程卡、二维码、横幅和品牌图读不到，用户只能去别的客户端看，或误以为客户端坏了。用户原话：「功能没起作用，无论怎么点击，邮件依然不显示图片（始终是空白）」。
- **现状（供设计定位，本卡不下结论）**：
  - 开关、状态机与 CSP 两档已实现并由 `SCN-0013` 的 L1/L2 覆盖：`MailboxToolbar` → `MailboxViewModel.setAllowsRemoteContent` → `MessageBodyView` → `MessageWebView` 以 `MessageBodyStyle.sanitized` 重载；放行档 `img-src data: https: http:`，阻止档 `img-src data:`。用户口语称「切换html邮件图片显示」；代码文案为「加载远程图片」，旧构建（`c1e93e6` 时间点）是正文内同名 `Toggle`，不是工具栏按钮。
  - 用户样本的 4/4 图片都是 `http://`（0 `https`、0 `data:`、0 `cid:`）；无脚本、无懒加载、无 CSS 背景图、无既有 CSP。`MessageBodyStyle.sanitized` 只注入 CSP/基础样式，不改写 URL，也不解析 `cid:`。
  - 应用 `Info.plist`（`Scripts/make-app.sh:15-33` 生成，`dist/uumail.app` 现有）**没有** `NSAppTransportSecurity`/`NSAllowsArbitraryLoadsInWebContent`；`Package.swift` 的 `uumail` 是无 bundle `Info.plist` 的可执行 target，`swift run` 与 `dist/uumail.app` 的 ATS 配置能力不同。
  - **首要根因假设（不是结论）**：macOS ATS 默认阻止 WKWebView 的明文 HTTP 子资源；`img-src` 只解决 CSP，不解决传输层。待设计用 L2 探针排除防盗链/Referer、主机不可达、旧构建等可能。
  - `SCN-0013` 的 `T-SCN-0013-02` 只断言 CSP 值与重载，未断言图片实际被请求/渲染；`SCN-0004` 的 `T-SCN-0004-03`（默认阻止不发请求）仍是代码审查级欠账。现状正好落在两张卡都没覆盖的缝里。
  - 需求阶段只读文档/代码与样本结构，未编译、未测量；根因与方案由设计证实。
- **非目标**：
  - 不改开关入口位置、形态、可用条件、单封会话内临时放行语义与工具栏顺序。来源：推导（`SCN-0013` 已验证；用户只反馈图片不显示）。
  - 不做自动加载、域名/发件人白名单、全局默认放行、开启 JS、放宽 `default-src 'none'`。来源：用户未提 + T5/D6 既有承诺。
  - 不做持久化偏好、每封记忆或跨会话保留；不改 schema、协议、数据所有权与公开契约。来源：推导（`REQ-0018` 已交付口径）。
  - 不做图片缓存、离线保存、图片放大/查看器、附件化。来源：假设（未经人工，D7）；若设计证明必须经应用代理取图（非缓存）才能显示，先改卡再扩，不静默扩成图片缓存功能。
  - 不为绕过防盗链伪造 Referer/Cookie。来源：假设（未经人工，D7）；若设计证明必须，先按 `auto-confirm` §3 提确认并改卡。
  - 不保证任意发送方的图片都可见：主机下线/防盗链/内容删除等外部原因导致的失败不算本卡回归；用户样本与等价受控夹具必须可见。来源：推导（外部不可控）。
  - 不把样本的图片数量、尺寸、URL 或「所有 http 图片」写成产品硬承诺；它们是现状样例。来源：`auto-confirm` §2。
- **约束**：
  - **放行后实际加载**：开启后当前正文的远程图片实际发起请求并渲染；不以「CSP `meta` 内容正确」「开关状态为 true」代替。来源：用户。
  - **阻止时零请求**：默认/关闭/无选中/加载中/失败时不得发起图片请求。来源：T5、`SCN-0013`/`SCN-0004`。
  - **单封临时放行不回归**：仅当前邮件、仅会话内；切换邮件/关闭/重开回到阻止，旧正文放行不泄漏。来源：`REQ-0018`/`SCN-0013` 已交付不变量。
  - **安全面最小**：禁 JS、`default-src 'none'`、白底与作者样式不变；修复只放宽「远程图片加载」所需的最小面。若需放宽 ATS 或其它应用级网络策略，属安全策略变更，须按 `auto-confirm` §3 取得人工确认，且只限 WebView 正文，不波及 EAS 既有网络路径。来源：`auto-confirm` §3 + T5。
  - **运行载体一致**：修复必须在用户实际运行的载体生效；release `dist/uumail.app` 与 `swift run` 的差异要有明确结论（配置、脚本或文档），不能只在一种方式下有效。来源：推导（现状事实）。
  - **不改架构契约**：不新增 target/第三方依赖；不改 `MailDomain`/`MailStore`/`Scenes` 公开契约；单文件 ≤300 行。来源：项目约定与架构门。
  - **隐私**：真实邮件样本只用于冒烟；自动化夹具用假 HTML + 受控图片源；evidence/日志不写真实主题、URL、主机、账号或凭据。来源：`af-flow-rule` §5。
- **影响场景**：
  - `SCN-0013`（`mail/read/remote-content-toggle`，现 `verified`）：**主验收场景**。新增/修改断言：用受控 http 图片源按「开前 0 请求 → 开启后请求到达并渲染 → 关闭后不再新增请求 → 切换邮件后 B 零请求」验证开关真实生效；单封隔离不退化。该卡是否由 `verified` 转 `designed` 再重验，由设计按 `af-flow-rule` §3 决定。需求不另立测试。
  - `SCN-0004`（`mail/read/message-read`，现 `designed`）：既有 `T-SCN-0004-03` 仍归该卡，覆盖「默认阻止 + 脚本不执行」的完整欠账（含 `<script>`）；本卡不代替它转 `verified`，也不把其欠账作为本卡交付门。
  - `SCN-0010`/`SCN-0012`/`SCN-0015`：回归白底、信封头、字号；不新增断言。
  - 可选新场景 `mail/read/remote-image-load`：由设计判断；需求建议优先 `SCN-0013` 增量，避免复制同一入口与运行序。
  - **设计落地（2026-11-19，记录设计对「由设计判断」项的选择，不改本卡口径/状态）**：选**新场景** `SCN-0018`（`mail/read/remote-image-load`，2026-11-19 收尾由 `designed` 转 `verified`）认领「实际加载/阻断零请求/交付载体」断言；`SCN-0013` 保持 `verified` 只读、不重开，其开关/状态机/CSP 断言继续作为回归。依据：`af-flow-rule` §7「已验证场景只读、重开需收尾按人工/需求确认翻转」与角色规则「新需求默认新场景」；边界见 `SCN-0018` 与 `task-spaces/20261119-213812/design.md` §7.1。根因已由 L2 证实为 ATS 传输层拦截（非 CSP），ATS 例外属安全策略变更，已按 D4 取得**人工确认**（2026-11-19 pass，仅加 `NSAllowsArbitraryLoadsInWebContent=true`；`doc/history/decisions/2026-11-19-remote-image-ats.md`）。
