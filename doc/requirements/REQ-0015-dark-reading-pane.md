# REQ-0015 深色主题下邮件阅读保持白底

- **ID**：REQ-0015
- **类型**：feature
- **场景叙述**：用户在深色主题下（系统深色且选择「跟随系统」，或在菜单里强制「深色」）打开一封邮件；正文内容区有一层不透明白色兜底，未声明背景的纯文本/HTML 邮件因此以白底深字正常显示。邮件作者显式声明的背景色、文字色、表格与图片样式保留；附件条、远程图片开关与截断提示等正文之外控件仍随应用主题。切换邮件、切换主题或重开窗口后规则不变。
- **价值**：不做则深色主题下 `MessageWebView` 的透明画布会把窗口深色背景透出来，而默认文字是深色，纯文本邮件出现「深底深字」几乎不可读；用户只能把系统切回浅色，等于深色模式不可用。
- **非目标**：
  - 不做阅读暗色/护眼/纸张主题，不做反色或自动暗化邮件。
  - 不把整个应用、侧栏、列表、工具栏强制白；白底只限正文内容区。
  - 不提供每封邮件的阅读底色切换，不改字体大小/行距。
  - 不改 T5（禁 JS、默认阻止远程资源）与正文 sanitizer 的安全策略。
  - 不改正文缓存、补拉、截断、附件下载与已读逻辑。
  - 不改作者显式背景/颜色来「统一成白」；白底是兜底，不是覆盖层。
- **约束**：
  - 正文白底不得依赖网络；切换主题不得重新拉取正文或改写正文内容，不得触发新的同步/写命令。
  - 白底兜底必须在正文 `.loaded` 状态成立；作者显式不透明背景可覆盖它；`.none`/`.loading`/`.failed` 占位可随应用主题，不强制白。
  - 默认文字色与白底保持现有深色对比（沿用 `#1d1d1f` 一类）；不得因深色主题变成浅色文字。
  - 作者显式声明的背景/文字色/表格/图片布局不得被兜底样式覆盖；无声明时才落白。
  - 不改 `FetchedBody`/`BodyPresentation` 的公共语义，不改 `MailDomain`/`MailStore`/`Scenes` 契约，不加依赖、不加 target、不改 schema。
  - 不新增 DB/Keychain/网络写入；主题偏好本身归 REQ-0016，不在本卡实现。
- **影响场景**：
  - `SCN-0010`（已建，`doc/design/scenarios/mail/read/dark-reading-pane/`，2026-11-16 由 `designed` 转 `verified`）：本卡唯一验收证据。新增「深色主题下无背景正文 → 不透明白底 + 深色文字」「主题来回切换/换邮件后仍白」「作者显式样式保留」三组正例与畸形/深色作者样式反例。
  - `SCN-0004`（已建，`designed`）：回归打开、缓存正文、占位补拉、截断与 CSP；不新增本卡断言，避免重复认领。
  - `SCN-0011`（已建，`doc/design/scenarios/settings/appearance/theme-switch/`）：只作为前置条件回归；主题切换不得取消本卡白底，断言归本卡/`SCN-0010`。
- **澄清记录**：
  - 2026-11-16 首轮需求分析，无人答问；以下按现有代码与最小改动收敛，设计开工前可改卡：
    - 「阅读背景」范围 = 正文内容区（`MessageWebView` 承载的正文画布），不含附件条、远程图片开关、截断提示与右侧栏；Q6 已于 2026-11-16 按 A 确认（`plan/open-questions.md` 已移除，结论见 `history/decisions/2026-11-16-theme-appearance.md`）。
    - 白底是兜底：无声明背景 → 白；作者显式背景（含深色主题邮件）→ 保留，不强行反色。若要求「一律白」，需另议并接受破坏作者样式。
    - 占位/加载/失败态不强制白，随应用主题；只有正文加载成功时白。
    - 与 `REQ-0004` 的归属：打开、缓存、补拉归 `REQ-0004`；本卡只负责深色主题下的阅读画布外观。`SCN-0004` 不重复认领。
