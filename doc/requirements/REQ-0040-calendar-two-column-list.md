# REQ-0040 日历页保留两栏与邀请列表

- **ID**：REQ-0040
- **类型**：`feature`
- **场景叙述**：用户切到「日历」时，窗口不再整块换成日历，而是保持与收件箱/发件箱相同的左列表 + 右内容两栏：左列按当前月/周列出会议邀请（主题、发件人/组织者、会议时间），一封会议邮件一行，重复会议只出现一次；右列是原来的月/周日历。单击左列或日历块都会选中同一场会议并高亮；双击左列或块打开同一个浮动阅读窗；Esc 取消选中。窗口收窄时先压日历，左列不窄于 320pt。
- **价值**：不做的后果——切到日历整窗变成一整块日历，顶部切换、左列位置和列表手感全部消失，用户会觉得「换了一个页面」而不是「换了一个邮箱」；同时日历里的会议没有一处列表可以扫读，重复会议只能靠网格找。
- **非目标**：
  - 不改月/周网格的投影算法、会议块定位、lane、全天条、ICS 导出与浮动阅读窗内容。
  - 不做日历事件的新建/编辑/拖拽、接受/拒绝邀请、日视图/年视图。
  - 不新增数据库字段/同步；不改 EAS、Outbox、Sent、收件箱/发件箱行为。
  - 不把左列做成可搜索/可筛选的第二个邮件列表；搜索仍只作用于邮件页。
- **约束**：
  - 日历与邮件共用同一个 `NavigationSplitView`；左列宽度 `min 320 / ideal 480`，右列日历取剩余。
  - 左列数据来自当前 `CalendarViewModel.occurrences`，按 `(folderID, serverID)` 去重，一封来源邮件一行；来源邮件已删除/移走时用会议主题、组织者、会议时间回退，列表不得因此缺行。
  - 单击选中/高亮、双击打开浮窗的语义与日历块一致；选中状态以 `CalendarViewModel.selectedOccurrence` 为唯一权威，左列与日历共享。
  - 行尾显示会议开始时间（全天显示「全天」），不显示收件时间；不改列表行图为已读/未读语义。
  - 只读本地库，零网络；不改 schema、target、依赖。
- **影响场景**：
  - `SCN-0024`（`calendar/browse/calendar-grid`）：新增两栏布局与邀请列表断言（`T-SCN-0024-10/11`），场景做增量重验。
  - 回归（不新增断言）：`SCN-0025`（浮窗打开）、`SCN-0028`（顶部三段切换）、`SCN-0023`（会议卡与 ICS）。
- **澄清记录**：
  - 2026-11-25 **人工确认**：左侧列**会议邀请邮件**（更接近收件箱列表），不是会议场次列表。
  - 2026-11-25 **人工确认**：单击选中、双击打开；两栏宽度沿用邮件页（列表 480、日历取剩余）。
  - 2026-11-25 默认（未经人工）：来源邮件缺失时用会议元数据回退；行尾显示会议时间；不做搜索/筛选。
- **状态**：`delivered`（2026-11-25 实现：`CalendarScene.message`、`CalendarMailItem`/`invitationMails`、`CalendarMailListView`、`CalendarReader`、`CalendarView` 共享选中、`MailboxView` 共用 split；466 tests / 77 suites、架构 4/4）
- **验收归属**：`SCN-0024` 的 `T-SCN-0024-10/11` 通过 + 上述约束逐条无违反 + 回归场景不退化；需求不另立测试。
