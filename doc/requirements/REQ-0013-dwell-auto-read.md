# REQ-0013 列表停留自动已读

- **ID**：REQ-0013
- **类型**：feature
- **场景叙述**：用户在邮件列表点选一封未读邮件（选中即打开阅读区），当前选中项连续保持 3 秒且应用在前台；该邮件在本机转为已读，列表小蓝点消失、主题字重回到常规。已读状态持久化，并在后台尽力回写服务器，使其他客户端可见。3 秒内切换选中、切换文件夹/搜索、删除该邮件或应用退到后台，计时取消；回到前台且该邮件仍选中时重新计满 3 秒。服务器回写失败不回滚本地已读、不弹错误。
- **价值**：不做则未读只能靠“点开”（现状点开也不置读），用户在列表里读完一封仍留着蓝点，未读列表逐渐失真；桌面邮件客户端按停留时长自动已读是基本预期。
- **非目标**：
  - 不做手动「标为已读」入口（归 `REQ-0019`/`SCN-0014`）、不做「标为未读」、右键菜单、全部已读/按文件夹已读。
  - 不做未读计数角标、已读回执、按发件人/规则自动已读。
  - 停留固定 3 秒，不做可配置。
  - 只处理当前选中的一封，不对列表中所有可见未读行同时计时。
  - 不做离线已读补写队列：回写失败时本地保持已读，服务器可能暂为未读；下次全量重建以服务器为准。
  - 不改打开邮件的缓存/补拉语义、同步窗口、通知与列表排序。
- **约束**：
  - 蓝点消失不得等待网络；本地已读必须持久化，服务器回写在后台完成且幂等。回写失败不阻塞 UI、不回滚、不弹错。
  - 计时必须用可注入时钟实现，测试不依赖真实等待 3 秒，并断言注入时长为 3 秒（防止回退到 10 秒或改短后无测试可查）。
  - 只对 `isRead == false` 的当前选中邮件触发；同一封重复计时不得重复回写。
  - 选中变化、文件夹切换、搜索、删除、应用失活都必须取消计时；回到前台重新计满 3 秒，不累计。
  - 已读回写与同步不得并发推进同一集合游标；写路径只能经场景，不得由视图或视图模型直接触网。
  - 核心 `MailGateway`/`SyncStore` 契约或 schema 变更属 P1，需人工确认后才开 change。
  - 不新增 target/组件；若设计认为必须新增，按 P1 结构决策另立，不在本批硬塞。
- **影响场景**：
  - `SCN-0008`（已建，`verified`，`design/scenarios/mail/read/dwell-auto-read/scenario.md`）：本卡唯一验收证据。2026-11-16 发起人要求把连续停留时长由 10 秒改为 3 秒；`SCN-0008` 需按 3 秒修订断言并重验（修订草案见 `task-spaces/20261116-223645/scenario-drafts.md` §SCN-0008 修订）。修订后须覆盖「选中未读、前台连续 3 秒 → 本地已读、蓝点消失并持久化」「2 秒切走/后台不足 3 秒不置读」「回到前台重新计满 3 秒」「回写失败不回滚」，并断言注入时钟收到 `.seconds(3)`。
  - `SCN-0004`（已建，`designed`）：回归打开、缓存正文、补拉失败路径；本卡不新增断言；其「已读标志未实现」说明已于 2026-11-14 设计任务中更新为「已读归 `SCN-0008`」。
