# REQ-0037 顶部三段邮箱切换

- **ID**：REQ-0037
- **类型**：`feature`
- **场景叙述**：用户启动应用后，窗口里不再有左侧文件夹栏；顶部工具栏在交通灯之后显示「收件箱 / 发件箱 / 日历」三段切换，默认停在收件箱。选收件箱或发件箱时，邮件页是「列表 + 阅读」两栏：列表在左、阅读区在右，列表默认 480pt、不窄于 320pt；选日历时，日历占满内容区，顶部三段切换仍在，不被邮件列表或阅读区挤走。草稿、已删除、垃圾邮件等其他文件夹不再出现在界面上，也没有入口。
- **价值**：不做的后果——左侧服务器文件夹列表很长，草稿、已删除、垃圾邮件等文件夹用户基本不用，却一直占掉侧栏宽度和每次选信的扫视成本；日历入口又埋在侧栏第一行，容易被当成普通文件夹。用户实际只去三个地方：收件、看已发送、看日历。把这三段固定到窗口顶部，去掉侧栏，列表和阅读区还能多出侧栏让出的宽度；不改列表内容与阅读路径，就能让常用动作始终在同一位置。
- **非目标**：
  - 不做文件夹管理、自定义顺序、显示/隐藏规则、拖拽排序或重命名；不为其他文件夹保留任何入口。
  - 不改列表 30 天窗口与计数、双击/Enter/空格打开浮窗、搜索范围与行为、窗口最小尺寸（900×560）。
  - 除刷新按钮按当前 section 分派外，不改工具栏按钮集合、顺序，也不改回复/全部回复/转发/标记已读/远程图片等既有动作。
  - 不改日历月/周视图内部布局、会议块定位与会议打开路径。
  - 不改 schema、不新增 target、不新增第三方依赖。
- **约束**：
  - 顶部切换在邮件页与日历页都**始终可见**：挂在根视图 toolbar 的 `.navigation` 位（leading，交通灯之后），不放进任一内容分支的局部 header；日历页不另起一套切换。
  - **默认收件箱**：启动时 `section = .inbox`；从邮件切到日历再切回时，按用户点选的收件箱/发件箱恢复，不引入跨启动记忆。
  - 邮件页为**两栏** `NavigationSplitView`：第一列是列表，`min 320 / ideal 480`；第二列是阅读区，取剩余宽度。不再有侧栏列，也不使用不遵守 `idealWidth` 的 `HSplitView`。
  - 列表、阅读区、搜索、选中、双击/浮窗、删除、已读、附件与撰写均沿用既有路径；本次只替换外层导航与分栏，不复制这些行为。
  - 其他文件夹不渲染、不可达；`reloadFolders` 仍保留，用于解析收件箱与发件箱的 serverID，不扩大同步范围。
  - 工具栏刷新按 section 分派：发件箱走发件箱刷新，其余走收件箱/全局刷新（发件箱同步口径见 `REQ-0038`）。
  - 不改 schema、target、依赖与窗口最小尺寸。
- **影响场景**：
  - **新建 `SCN-0028`（`mail/receive/mailbox-sections`）**：认领「顶部三段 + 无文件夹栏」「1440/900 两栏宽度」「发件箱/日历切换」「快速切走不抢回 + 无 Sent 空态」的 3 正 1 反。
  - 回归（不新增断言，不作为本卡验收证据）：`SCN-0025`（双击/Enter/空格与浮窗）、`SCN-0024`（日历月/周与会议打开）、`SCN-0027`（列表 `min 320 / ideal 480` 宽度口径；其三栏中的侧栏宽度断言随侧栏移除而失效，两栏宽度改由 `SCN-0028` 承接）。
