# REQ-0025 HTML 正文内联图片（`cid:`）显示

- **ID**：REQ-0025
- **类型**：feature
- **场景叙述**：用户打开一封正文以 `cid:`（Content-ID）引用内联图片的 HTML 邮件（常见于 Outlook/Exchange 发出的招聘通知、海报、行程单），期望**打开就能在正文里看到图片**，不需要先去点附件条里的 `image001.png`，也不需要先点「加载远程图片」。用户样本邮件：正文区整块空白，附件条同时列出 `image001.png`、`image002.png` 两个 `imageNNN.png` 形态的附件；用户追问「是否因为没有实现负载下载的功能」。
- **价值**：这类邮件的正文主体常常就是图片（招聘海报、活动通知、票据/行程图），图片不显示等于整封邮件读不到；用户只能去别的客户端看，或误判客户端坏了。用户原话：「这个邮件还是无法显示图片」。把内联图片接通，是「阅读 HTML 邮件」这条主流程在真实企业邮件上的可用性底线。
- **现状（供设计定位；本卡不下根因结论）**：
  - **正文负载已实现**：打开邮件时 `ReadScene.open` 走 `MailGateway.fetchBody` → `EASClient.fetchBody`（`ItemOperations` Fetch，`BodyPreference/Type=2` HTML，200000（网关按字节计）上限、`Truncated` 时免上限重取）→ `MailStore.applyBody` 落 `message_bodies`。因此「正文根本没下载」不成立。
  - **附件负载下载原语已实现**：`EASClient.fetchAttachment(fileReference:)`（`ItemOperations` Fetch `FileReference`，base64 解码）→ `ReadScene.downloadAttachment`（缓存命中、单飞、`AttachmentFiles` 落盘、`markAttachmentCached`）；但**只**由附件条的点击触发，结果交给系统打开，**从不回填正文**（`MessageBodyView.attachmentStrip` → `MailboxViewModel.download`）。
  - **EAS 附件元数据只保留了三个字段**：`EASAttachment{displayName,fileReference,size}`；`eas_tokens.json` 里虽有 `ContentId`/`ContentLocation`/`IsInline` 词条，解析器没有读，`MailDomain.Attachment` 与 `attachments` 表（v4 schema）也没有 content-id / inline 标记列。
  - **正文渲染不做任何 URL 改写**：`MessageBodyStyle.sanitized` 只注入 CSP 与基础 CSS；两档 CSP 分别是 `img-src data:` 与 `img-src data: https: http:`，**都不含 `cid:`**；`MessageWebView` 用 `loadHTMLString(_, baseURL: nil)`。即使打开「加载远程图片」，`cid:` 也没有解析器/处理器。
  - **截图形态**：附件条与空白正文同屏；按现行 `MessageBodyView`，附件条只在正文 `.loaded` 分支渲染（`MessageBodyView.swift:84-94`），故形态与「正文已加载、但内容不可见」一致（设计需按用户实际运行版本复核）。
  - **待设计证实的样本假设（不是结论）**：该样本正文 HTML 以 `cid:` 引用这两个内联附件，且正文没有可见文字（或文字极少）；网关 Sync 的 `Attachments` 是否返回 `ContentId`/`IsInline`、`cid:` 值与附件如何对应，均需 L2/线格式核实。若证实正文另有问题，设计按证据回退改卡。
  - **结论口径**：用户的直觉方向（与「负载下载」有关）**部分成立**——下载原语存在，缺的是「识别内联附件 → 取负载 → 把 `cid:` 替换为可渲染内容 → 放行 CSP」这条链路。需求阶段只读文档/代码/截图，未编译、未测量。
- **非目标**：
  - 默认不改正文文本的 HTML/截断语义与既有 EAS 命令形状；但若设计证明只有换一种取正文/附件的方式（如 MIME 负载）才能拿到内联图片，先在设计中说明代价并按契约/安全变更处理，不静默改、也不为省事把整条 EAS 读取链路重写。来源：推导（现状正文已工作；是否需扩协议待 Q2 实测）。
  - 不重做附件条、附件下载/打开、25MB 上限、断点续传、`AttachmentName` 回退（这些是 `SCN-0005` 的既有欠账）。来源：推导（用户只反馈正文图片不显示）；若本卡实现复用附件路径，只要求不回归。
  - 不自动加载远程 `http(s)` 图片、不改「加载远程图片」开关的位置/默认值/单封临时放行语义、不为防盗链伪造 Referer/Cookie。来源：`SCN-0013`/`SCN-0018` 已验证承诺 + 用户未提。
  - 不做图片查看器/图库/手动离线保存/图片编辑。来源：假设（未经人工，D6）；内联图片必要的内存/临时/缓存落盘由设计决定，不算「图片缓存功能」。
  - 不做撰写端插入/上传内联图片（`REQ-0021` 已明确不做）。来源：`REQ-0021` 非目标。
  - 不保证任意畸形邮件都能显示：`cid:` 无对应附件、附件损坏、超时等外部/坏数据失败不要求图片可见，但**正文文本必须照常可读**。来源：推导（外部不可控 + 阅读可用性）。
  - 不把样本的附件名、图片数量、尺寸或「所有 `cid:` 邮件」写成硬契约；它们是样本样例。来源：`auto-confirm` §2。
- **约束**：
  - **打开即可见**：内联图片在正文中显示（可辨识、非破图、保持作者尺寸约束），不要求用户先点附件条或先开「加载远程图片」。来源：用户（图片应显示）+ 假设（未经人工，D2；内联图片是邮件自身内容，不是远程资源）。
  - **只取当前邮件实际引用的内联附件**：不预取未被正文引用的附件；不因 `cid:` 向第三方主机发请求。来源：推导（T5/R7 隐私底线）。
  - **远程图片门控不回归**：默认/关闭时远程 `http(s)` 图片仍 0 请求；开关仍单封、会话内、切换复位。来源：`SCN-0013`/`SCN-0018` 已验证。
  - **安全面最小**：禁 JS、`default-src 'none'`、白底与作者样式不变；若必须放宽 CSP（例如允许某种本地 scheme），只放宽内联图片所需最小面，**不得**让 `http(s)` 默认放行。来源：T5/R7。
  - **失败不空白**：引用的附件缺失、取负载失败、base64/解码失败时，正文文本仍可读，不整页空白、不崩溃、不无限重试。来源：推导（用户痛点正是「整块空白」）+ `SCN-0004` 阅读可用性。
  - **不新增第三方依赖/target**；单文件 ≤300 行（既有架构门）。来源：项目约定/`AGENTS.md`。
  - **契约变更需确认**：若实现需要改 `MailDomain`/`MailStore` 公开契约或 `attachments` schema（如新增 `content_id`/`is_inline`），属契约变更，由设计按 `auto-confirm` §3 提人工确认；本卡不默认批准，也不允许静默加列。来源：`auto-confirm` §3.1。
  - **样本脱敏**：真实邮件只做冒烟；自动化夹具用假 HTML + 受控附件；evidence/日志不写真实主题、发件人、URL、账号或凭据。来源：`af-flow-rule` §5。
- **影响场景**：
  - **新建 `mail/read/inline-image-render`（建议 `SCN-0019`）**：主验收场景，认领「打开即可见 / 不依赖远程开关 / 失败不空白 / 无第三方请求」的 3 正 1 反。理由：这是一个独立结果（内联图片渲染），`SCN-0018` 已验证且明确把 `cid:` 解析排除在不可变引用之外；`SCN-0005` 只认领附件点击下载；`SCN-0004` 认领正文基本渲染，均不能覆盖本结果。最终由设计判断。
  - `SCN-0018`（`remote-image-load`，`verified`）：只回归「远程开关/ATS 载体」，**不新增断言**；本卡不得改写其「不做 `cid:` 解析」的边界。
  - `SCN-0013`（`remote-content-toggle`，`verified`）：只回归开关状态机/默认阻止/切换复位。
  - `SCN-0005`（`attachment-download`，`designed`）：只回归附件下载/打开；本卡不替它补 25MB/续传/名称回退。
  - `SCN-0015`（`font-size`）与 `SCN-0010`（`dark-reading-pane`）：只回归字号缩放、白底与图片/表格不溢出。
  - 需求不另立测试；验收 = 新场景的 3 正 1 反（建议 `SCN-0019`；可执行 ID 由设计定）通过 + 上述回归不退化 + 约束逐条无违反。
