# REQ-0035 阅读浮窗默认位置居中

- **ID**：REQ-0035
- **类型**：`quality`
- **场景叙述**：用户双击列表行、在列表里按 Enter / 空格，或从日历双击一场会议打开阅读浮窗时，浮窗默认出现在**主窗口的正中央**——浮窗中心与主窗口中心重合——而不是贴在主窗口右上角。主窗口靠近屏幕边缘时，浮窗整体仍落在屏幕可用区内，不露出屏幕外。用户把浮窗拖到别处后，关闭再打开、或重启应用，浮窗回到用户最后放置的位置；从未拖动过时，每次新建浮窗都重新居中。
- **价值**：不做的后果——旧实现把浮窗固定放在主窗口右上角，主窗口居中或靠左时，浮窗离用户正在看的列表行很远，读起来像「另一个窗口」而不是从当前内容长出来的。默认居中符合「从当前内容打开」的空间预期；记住拖动后的位置则避免用户每次都要重新摆放。
- **非目标**：
  - 不改浮窗尺寸口径（宽取阅读区、高取主窗口 85%、下限 480×460），不改单例、工具栏、远程图片默认显示、打开即已读、就地撰写。
  - 不改主窗口位置、尺寸或主窗口自身的记忆。
  - 不做每屏独立位置、多显示器分别记忆、吸附/磁贴/跟随主窗口移动。
  - 不改 schema、不新增 target、不新增第三方依赖；不新增用户可见设置项。
- **约束**：
  - **默认位置** = 以主窗口中心为浮窗中心，再把浮窗整体夹进主窗口所在屏幕的可用区（`visibleFrame`）；夹取优先保证整窗可见，浮窗大于屏幕时贴可见区的最小原点（`visible.minX/minY`）。
  - **只对「用户没摆过」的浮窗生效**：用户尚未拖动过位置时，每次新建浮窗（启动后首次打开，或关闭后再次打开）都按当前主窗口重新居中；用户拖动过之后，保存的位置优先，不再自动居中。
  - **跨启动记忆**：拖动后的位置写入新的窗口保存键 `uumail.reader.centered`；不读取旧键 `uumail.reader` 的历史右上角位置，避免升级后第一次打开仍回到右上角。尺寸记忆沿用 `REQ-0031` 的口径。
  - 主窗口几何不可得（首启、窗口尚未布局）时退回系统默认位置，不阻塞打开，也不把浮窗放到屏幕外。
  - 位置计算是纯函数，可在 L1 直接断言；不依赖真实鼠标事件即可验证。
- **影响场景**：
  - `SCN-0025`（`mail/read/floating-reader`）：新增默认居中与拖动记忆的验收断言（`T-SCN-0025-05`），场景做增量重验。
  - 回归（不新增断言）：`SCN-0024`（日历双击打开同一浮窗，位置规则一致）、`SCN-0023`（会议卡内容不变）。
- **澄清记录**：

  - 2026-11-24 **人工确认**：用户拖动过位置后要记住（跨启动），不采用「每次打开都居中」。
  - 2026-11-24 **人工确认**：只换新的窗口保存键，不迁移旧右上角位置；尺寸口径不变。
