# REQ-0034 邮件列表默认列宽

- **ID**：REQ-0034
- **类型**：`quality`
- **场景叙述**：用户打开应用，或在顶部切到「收件箱 / 发件箱」时，邮件页按两栏分配：邮件列表默认 **480pt**、阅读区取剩余宽度（顶部三段切换与无文件夹栏见 `REQ-0037`）。发件人、主题与收信时间在列表里有足够的默认宽度，不再挤在 380pt 里频繁横向截断。窗口从 1440 收窄到应用最小宽 900 时，先压缩阅读区，列表保持 480pt；列表在任何窗口下都不低于 320pt，不出现被压成窄条或负宽。拖拽分栏、切换收件箱/发件箱的行为保持不变。
- **价值**：不做的后果——列表是选信的主战场，默认 380pt 下长主题、较长的中文发件人与时间列互相挤压，用户每换一个窗口尺寸或每次拖大列表都在重复同一件事。只调大默认值、不动任何交互，就能让常见窗口下的列表回到可扫读宽度；阅读区仍有余量承接正文。
- **非目标**：
  - 不做列宽切换、预设列宽、双击列头自适应，也不新增列宽持久化或重启恢复；拖拽分栏行为不变。
  - 不改列表行内容、行高、列序、排序、选中/双击/键盘行为。
  - 不改窗口最小尺寸（900×560）；不改顶部导航与两栏结构（由 `REQ-0037` 负责）、不改日历页分栏。
  - 不改 schema、不新增 target、不新增第三方依赖。
- **约束**：
  - 列宽用最小/理想约束表达：列表 `min 320 / ideal 480`；阅读区不设理想宽，取剩余空间，不写死任何一列的绝对宽度。
  - **变窄时先压阅读区**：列表在空间足够时保持 480pt，只有剩余空间不足时才向 320pt 下限收缩；任何情况下列表不得出现 0 或负宽，也不得把阅读区压成负值。
  - 观测口径（L2 两栏探针）：1440 窗口 = 列表 480 / 阅读 952；1200 = 480/712；1000 = 480/512；900（应用最小宽）= 480/412；760（低于应用最小宽，探针强设）= 480/272。
  - 切换收件箱/发件箱、搜索、选中、双击打开浮窗仍走既有路径，列宽变化不改变这些行为。
  - 不因列宽调整引入横向滚动条或行内换行。
- **影响场景**：
  - **`SCN-0027`（`mail/receive/list-layout`）**：认领「1440 两列宽度」「1200/1000/900 列表保持 480」「760 列表不低于 320」「极窄窗口不得出现 0/负宽」的 3 正 1 反；2026-11-24 去掉侧栏后按两栏重验。
  - 回归（不新增断言，不作为本卡验收证据）：`SCN-0028`（顶部三段切换）、`SCN-0026`（列表 30 天窗口与计数）、`SCN-0025`（双击打开浮窗）、`SCN-0009`（列表身份与删除）。
- **澄清记录**：
  - 2026-11-24 **人工确认**：列宽只调大默认值（列表 `280/380` → `320/480`），不做列宽切换或重启记忆。
  - 2026-11-24 默认（未经人工）：最小宽 320pt 与理想宽 480pt 即验收取值；760 档低于应用最小宽 900，只作探针鲁棒性检查。
  - 2026-11-24 **结构变更**：用户确认「日历/收件箱切换放顶部、去掉文件夹栏」（`REQ-0037`），邮件页由三栏变两栏；本卡的侧栏 220 断言作废，列表 320/480 口径保留，`SCN-0027` 按两栏重验。
