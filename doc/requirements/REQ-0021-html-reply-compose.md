# REQ-0021 回复撰写支持 HTML 富文本与完整关闭

- **ID**：REQ-0021
- **类型**：feature
- **场景叙述**：用户在阅读页点「回复」「全部回复」「转发」或工具栏「新建」，撰写 sheet 打开一个 HTML 编辑器：原邮件 HTML 以全宽直接出现在光标下方（不缩进、不用 `blockquote`），上方有格式栏（加粗、斜体、下划线、删除线、字号、左/中/右对齐、项目符号/编号、清除格式）。用户可以像写富文本一样编辑，发送后支持 HTML 的客户端看到排版，纯文本客户端看到由同一内容生成的纯文本；存草稿/发送把 HTML 一起落库并进入 outbox。sheet 顶部有 `xmark`、底部有「取消」：有改动时二次确认，无改动直接关闭，取消不写库、不投递。sheet 默认宽度等于当前阅读窗格（detail 列）宽度。
- **价值**：现有撰写页是纯文本 `TextEditor`，原邮件的表格、图片、颜色和签名全部丢失，回复带排版邮件只能去别的客户端；也没有取消入口，用户只能发送或存草稿；固定 640pt 的 sheet 与阅读窗格宽度不一致，回复长邮件时阅读与撰写视线来回跳。
- **非目标**：
  - 不做附件添加、内联图片上传、字体家族/文字颜色/背景色/插入图片/表格/超链接/查找替换；格式栏只覆盖上面列出的 10 个动作。
  - 不做草稿箱列表/草稿继续编辑 UI（仍沿用 outbox 的 `draft` 行，不在本卡展开）。
  - 不做多窗口撰写、不做独立撰写窗口、不做 Apple Mail 式浮动格式栏。
  - 不改 EAS 协议、不改发送通道、不改 `Outbox` 状态机、不改 `ClientId` 幂等；不新增第三方依赖或 target。
  - 不做远程图片的新开关；编辑器沿用阅读区「加载远程图片」的会话开关（默认关）。
  - 不改新建/回复/转发的收件人、主题、会话头规则（`REQ-0012`/`REQ-0007` 的既有断言不重写）。
- **约束**：
  - 发信格式必须是 `multipart/alternative`：`text/plain`（纯文本兜底）+ `text/html`（编辑内容）；仅当 HTML 为空时才退回单段 `text/plain`。两段必须来自同一份编辑内容，不能各写一套。
  - 引文必须全宽、无缩进：不得生成 `<blockquote>`、`margin-left` 或左边框；抬头是日期 + 原发件人 + `写道：`（转发用 `---------- 转发邮件 ----------`）。
  - 原邮件 HTML 必须清洗后再进入编辑页：移除 `script`/`iframe`/`object`/`embed`/`form`/`input`/`button`/`textarea`/`select`/`meta`/`link`/`base`、`on*` 事件属性与 `javascript:` URL；编辑页使用 `default-src 'none'`、无 `script-src` 的 CSP，页面脚本不得执行，格式命令由 app 注入 `evaluateJavaScript`。
  - 编辑器必须可编辑、可撤销；`capture` 后写回的内容不得包含编辑器 CSP、编辑器样式、`contenteditable`/`spellcheck` 属性。
  - 取消语义：未改动 → 立即关闭；有改动 → 二次确认「放弃 / 继续编辑」；「放弃」不写 outbox、不投递；「继续编辑」保持内容与 sheet。
  - sheet 默认宽 = 阅读窗格宽度（低于 480pt 时保 480 可用下限），默认高 = 阅读窗格高度（460…820pt 夹取）；不新增窗口最小尺寸、不改阅读区布局。
  - 不回退字号能力：`REQ-0020` 五档字号下格式栏/字段/按钮可缩放、编辑器 `pageZoom` 跟随；100% 下既有界面基线不漂移。
  - 不写业务库/Keychain/网络以外的持久化；撰写打开不触网（原邮件正文使用阅读区已加载的 HTML）。
  - macOS 14+，只用 SwiftUI/AppKit/WebKit 标准能力。

  - `SCN-0006`（发送）：回归发送只入队、失败保留、`Cc:` 头；不新增断言。

  - `SCN-0015`（字号）：回归撰写 sheet 的缩放与 100% 基线；不新增断言。
