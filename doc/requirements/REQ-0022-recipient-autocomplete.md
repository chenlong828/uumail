# REQ-0022 撰写页收件人输入联想补全

- **ID**：REQ-0022
- **类型**：feature
- **场景叙述**：用户在撰写页（新建/回复/全部回复/转发）的收件人或抄送输入框里输入少量字符时，输入框下方出现候选提示框；候选来自本地已同步邮件的发件人/收件人/抄送缓存，每行显示「人名 + 邮箱」，没有名字时只显示邮箱。候选随每次输入刷新，用户用鼠标或键盘选中后，当前收件人补全完成，其余已填地址不动；没有候选时静默不显示，手动输入、粘贴、发送/存草稿等既有行为不变。
- **价值**：不做则用户每次要手抄或从别处复制长邮箱地址，慢且容易错人；本地已收邮件里已有大量真实联系人与地址，却不能用于下一次撰写。现状是纯 `TextField`，没有任何联想入口（`Sources/uumail/ComposeView.swift:33-34`）。
- **非目标**：
  - 不接 GAL/Exchange 目录、不做服务器端 `Search`/`Find`、不接 macOS 通讯录；不新增任何网络请求。`GAL` 不可用、联系人只做本机通讯录 + 收件人历史是既有架构承诺（`doc/design/architecture.md:47`、`:445`）。
  - 不做已发送/Sent 镜像、outbox/草稿、附件或正文作为联系人来源；首版只从**已收邮件信封**的 `sender`/`recipients`/`cc` 提取。
  - 不做联系人管理页/通讯录编辑/分组/收藏/黑名单/权重学习；不做空输入时的「最近联系人」列表，只在有输入片段时给候选。
  - 不做拼音/首字母/模糊音检索；中文名只按已存储的显示名文本做前缀/子串匹配。若发起人要拼音，先改本卡再设计。
  - 不做收件人字段的 token/芯片化重构；不把显示名写进 `To:`/`Cc:` 头；不改 MIME、RFC 2047、`Outbox`、发送通道与投递语义。
  - 不做自动选中/自动发送；不做多账号切换；不做按邮件/按文件夹的联系人来源筛选。
  - 不改新建/回复/全部回复/转发的收件人种子规则（`REQ-0007`/`REQ-0012`），不改撰写页的 HTML 编辑器、格式栏、取消确认与等宽 sheet（`REQ-0021`）。
- **约束**：
  - **数据源与新鲜度**：候选只读本地库已同步邮件的 `sender`/`recipients`/`cc`；打开撰写页时可加载（预载或首次聚焦懒加载由设计定），但输入刷新不得逐键查库（内存过滤/预载）。新同步邮件在后续打开撰写页时可用；不要求撰写页打开期间实时增量刷新当前候选列表。
  - **账号与地址范围**：按当前账号隔离；排除当前账号自己的地址；排除收件人/抄送字段中已经存在的地址（大小写不敏感）；跳过裸显示名、通讯组名、Exchange DN 等非 SMTP 段，不展开通讯组、不解析目录。
  - **候选内容**：每行显示「显示名 + 邮箱」，显示名缺失/空白时只显示邮箱，不得出现空名字占位、`nil`、`<>`；同一地址有多个名字时取最近一次非空名字或等价的稳定规则，不得在相邻输入间随机跳变。
  - **触发与刷新**：空片段不显示；输入 1–2 个字符即可出现候选，不得要求输入完整地址（具体阈值由设计定并写进场景卡）；字段文本每次变化都刷新候选，无需额外点击/快捷键；候选条数有上限（建议 5–8，设计定，必须可测）。
  - **匹配**：至少覆盖邮箱地址的前缀/子串与显示名的前缀/子串；大小写不敏感；同一候选只出现一次；排序要稳定（建议匹配度优先，其次最近出现；具体算法由设计定，但同一输入的候选顺序必须可复现）。
  - **选择与插入**：选中后把当前正在输入的尾片段替换为**纯邮箱地址**并补 `; `；其他已填地址、`Cc`、主题、正文、编辑器状态都不动；已在字段中的地址不得重复插入。只在片段位于字段末尾时替换；光标在中间/有选区时不得改乱已有文本（可只隐藏候选，不自动插入）。
  - **不改发送语义**：选中写入的必须是现有 `AddressList`/发送链路可接受的纯地址；`To:`/`Cc:` 头不得出现未编码的非 ASCII 显示名。`ComposeViewModel.draft`/`Outbox`/`MimeBuilder` 的既有行为不变（`Sources/Outbox/MimeBuilder.swift:10-13`）。
  - **无候选与失败**：无本地数据、无命中、候选加载失败时静默不显示，不报错、不阻塞撰写；手动输入、粘贴、多收件人、`Cc` 输入、发送/存草稿、回复预填保持现状。
  - **交互安全**：候选默认不高亮；`Return` 只在用户主动方向键选择后才提交，不得干扰中文输入法的候选词确认；`Esc` 可收起；候选行可点击、可键盘导航，鼠标/键盘操作不抢走字段焦点。
  - **界面一致性**：候选提示框跟随 `REQ-0020` 五档字号缩放、跟随浅色/深色主题且可读；100% 档不改变现有表单布局基线；候选框不得遮挡输入焦点或把 sheet 撑破；候选行有无障碍标签。
  - **性能**：按当前真实库量级（2026-11-18 只读聚合：125 封已收邮件、647 个去重地址）一次预载 + 内存过滤；每次按键刷新不得产生可感知卡顿。更大量级时的降级/上限由设计写清，不得阻塞撰写。
  - **隐私**：联系人/地址只在本地使用，不联网、不导出、不写日志、不进 evidence；候选数据不得离开本机。
  - **架构与预算**：`Presentation` 不得 `import MailStore`，目录查询必须经 `Scenes` 暴露（架构门 1）；不新增 target/第三方依赖。`MailStore` 组件当前实测 **1008 行**，已超规格 **1000 行硬上限**（`task-spaces/20261118-080109/evidence/code-scan.log` §8b）；若设计新增联系人表/查询，先拆分或走 P1 预算调整确认，不得静默超限。`ComposeViewModel` 当前 263/400 行、`ComposeView` 当前 172/300 行；新增联想状态/候选控件后仍须在单文件预算内，超限先拆 extension/helper。
  - **范围变更提示**：若设计选择新增联系人 `schema`（如 v11 `contacts` 表）或新增 `MailDomain`/`ComposeScene` 公开契约，属 P1，必须由设计节点按 `auto-confirm` 记录默认确认（未经人工）并交评审判断；回退方式是降级为「打开撰写页时扫本地 `messages` 内存聚合 + 会话内缓存」，不改 schema。
- **影响场景**：

  - `SCN-0006`（发送）：回归手动输入/粘贴、空收件人拒绝、发送只入队；不新增断言。
  - `SCN-0007`（全部回复）：回归 To/Cc 预填与去重；联想不得改写种子；不新增断言。
  - `SCN-0016`（HTML 撰写）：回归 To/Cc 字段、HTML 编辑器、取消与等宽 sheet；不新增断言。
  - `SCN-0015`（字号）：回归撰写页在 5 档字号下既有控件不退化；候选框自身的缩放由 `SCN-0017` 断言，不写进 `SCN-0015`。
