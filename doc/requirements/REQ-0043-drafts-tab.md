# REQ-0043 草稿箱 tab 与右侧就地继续编辑

- **ID**：REQ-0043
- **类型**：`feature`
- **场景叙述**：主窗口顶部三段切换增加第四段「草稿箱」，排在「发件箱」与「日历」之间。切到草稿箱后，左侧列出本机保存的草稿（最新在前，显示主题、收件人、更新时间）；单击一封草稿，右侧直接进入编辑态继续写：标题为「草稿」，顶部是红色关闭、`存草稿`（⌘S）与蓝色「发送」，收件人/抄送/主题/正文都按草稿内容回填。点「存草稿」覆盖当前这一条并留在编辑器（状态行显示「草稿已保存」，左侧列表同步刷新）；点「发送」把这一条草稿转成待发邮件，编辑器关闭、该行从草稿箱消失。切换到别的 tab 或选中另一封草稿时，当前未保存的修改先自动存回原草稿。没有草稿时显示「没有草稿」空态。
- **价值**：不做的后果——「存草稿」写完就关、草稿只存在于数据库里，用户没有任何入口看见或继续写；写了一半的邮件等于丢失。草稿箱让「写到一半—离开—回来接着写」成立，并且由于复用同一行，重复保存不会堆出多份草稿、发送后也不会残留。
- **非目标**：
  - 不显示/同步服务器 Drafts 文件夹里的草稿；草稿只来自本机「存草稿」（服务器同步另立需求）。
  - 不做删除草稿、批量操作、搜索、排序切换、草稿附件。
  - 不改撰写 sheet（新建/回复/转发）的形态与语义；不改格式栏、收件人联想、编辑器实现。
  - 不改发送入队/投递语义（发送仍只入队，Outbox 冷投递）。
  - 不改 schema、不新增 target/依赖。
- **约束**：
  - 草稿是 `outbox` 表里 `state = 'draft'` 的行；列表按 `updated_at DESC, id DESC` 读取。
  - 从草稿箱打开的编辑器持有该行 id：`存草稿` 执行 `UPDATE`（同一行、刷新 `updated_at`），不会插入第二行；行已被删时回退为插入新草稿。
  - `发送` 把同一行原子地改为 `state = 'queued'`、`is_draft = 0`（同一 `ClientId`），草稿箱不再列出该行；再走既有 Outbox 投递。
  - 右侧编辑器是就地嵌入（不是 sheet）：宽度跟随详情列、高度自适应；顶部多一个 `存草稿`（⌘S）按钮；关闭仍走「存储草稿？/放弃/继续编辑」确认。
  - 离开草稿箱 tab 或切换另一封草稿前自动保存未保存修改；自动保存失败则保留编辑器与内容，不静默丢弃。
  - 空态「没有草稿」与「选择一封草稿」两处文案；草稿主题为空显示「无主题」，收件人为空显示「未填写收件人」。
  - 本地时间显示 `MM-dd HH:mm`，字体沿用五档字号基线。
- **影响场景**：
  - 新建 `SCN-0031`（`mail/send/drafts`）：草稿列表、就地继续编辑、保存同行、发送消费草稿、自动保存与空态。
  - 回归（不新增断言）：`SCN-0016`（sheet 撰写不变）、`SCN-0028`（顶部切换新增一段仍保持 leading）、`SCN-0006`（发送仍只入队）、`SCN-0017`（收件人联想在草稿编辑器内可用）。
- **澄清记录**：
  - 2026-11-26 **人工确认**：草稿箱显示本机保存的草稿，不同步服务器 Drafts 文件夹。
  - 2026-11-26 **人工确认**：在右侧点「存草稿」后留在编辑器继续写，不返回列表。
