# REQ-0018 远程图片开关并入工具栏

- **ID**：REQ-0018
- **类型**：feature
- **场景叙述**：用户打开一封含远程图片的邮件。阅读区不再有一行独立的「加载远程图片」开关；该开关位于窗口顶部主工具栏，与新建、回复、全部回复、转发、刷新并列。开关默认关闭；用户打开后仅当前这封邮件临时放行远程图片，关闭开关或切换邮件后恢复默认阻止。开关不改变禁 JS 与其它 CSP 限制，也不写入偏好。
- **价值**：不做则阅读区正文上方多出一条像工具栏的控件行，和顶部真正的工具栏视觉割裂；用户找回复/转发时看到中间又多一层，容易误以为是第二条工具栏，也让正文可用高度变小。
- **非目标**：
  - 不改 T5：不关闭/放宽禁 JS，不全局放行远程资源，不做发件人/域名白名单，不做自动加载。
  - 不做「有远程图片才显示开关」的内容检测；不在本批新增 MIME/HTML 扫描或网关字段。
  - 不做开关状态持久化（不写 `UserDefaults`/业务库/Keychain），不做全局偏好、每封独立记忆或跨会话保留。
  - 不做右键菜单、快捷键、自定义工具栏、独立工具条或第二处入口。
  - 不改附件条、截断 banner、信封头、列表/侧栏、主题菜单、搜索、已读、删除、同步与发送。
  - 不改 `MailDomain`/`MailStore`/`Scenes` 契约、schema、协议；不新增依赖/target。
- **约束**：
  - 入口必须在窗口主工具栏（与新建/回复/全部回复/转发/刷新同一 `toolbar`），正文区域不再出现同名/同功能控件；不新增第二条工具条。
  - 默认关闭；放行只作用于当前选中邮件；切换选中邮件后必须回到关闭，旧邮件的放行不得泄漏到新邮件。这是 D6「单封临时放行」的既有语义，不是新策略。
  - 开启只改变当前正文的 `allowRemoteContent`（CSP 的 `img-src` 一档），禁 JS、`default-src 'none'`、白底与作者样式语义不变；关闭后立即恢复阻断。
  - 无选中、正文尚未加载（`.none`/`.loading`）或加载失败（`.failed`）时，开关不得可用；不得因此触发正文补拉、同步或远程请求。
  - 开关状态变化只重渲染当前正文，不改正文 HTML/sanitizer；主题切换不重载正文、不改变开关状态。
  - 工具栏在默认窗口下限（900×560）内不得挤掉新建/回复/转发/刷新，也不得溢出到不可操作；具体控件形态（开关/按钮/菜单）由设计定。
  - 视图只绑定视图模型，不直接读 `Message`/HTML/不拼 CSP。若设计需要给 `MailboxViewModel` 新增 public 状态或方法，按 P2 契约变更提确认，本卡不代签。
  - 测试用假 HTML/假邮件，不写真实邮箱、主题、图片 URL 或凭据到日志/证据。
- **影响场景**：
  - `SCN-0013`（待新建，草案见 `task-spaces/20261116-223645/scenario-drafts.md`，建议路径 `doc/design/scenarios/mail/read/remote-content-toggle/`）：本卡唯一验收证据；新增「开关在窗口主工具栏且正文无重复入口」「开启/关闭改变当前正文 CSP」「切换邮件回到关闭、不泄漏」「无选中/未加载/失败时不可用」断言。
  - `SCN-0004`（已建，`designed`）：回归正文打开、缓存、补拉、截断与 CSP；本卡不新增它的断言，`SCN-0004` 的 CSP 自动化欠账（`T-SCN-0004-03`）不由本卡补。
  - `SCN-0010`（已建，`verified`）：回归深色主题下正文白底与工具栏跟随主题；远程开关从正文行移到工具栏后仍随应用主题，不强制白；本卡不新增白底断言。
- **澄清记录**：
  - 2026-11-16 首轮需求分析（发起人只给一句话诉求，无人答问；以下按现有代码与最小改动收敛，设计开工前可改卡）：
    - 原文「加载远程图片的选项框直接站了一层工具栏，很突兀，应该同顶部的回复邮件等考虑放一块儿」：读作「把正文上方独立一行的开关移到窗口主工具栏，与回复/转发等动作同组」；不是新增第二工具栏，也不是删掉该功能。
    - 开关仍是**按邮件临时放行**（D6），不是全局偏好；切换邮件回默认关。现状 `MessageBodyView` 的 `@State` 可能跨邮件复用，本卡要求设计修正为按当前选中邮件重置（见 `plan/risks.md` R33）。
    - 开关可用性：默认「有选中且正文已加载才可用」，无选中/加载中/失败时禁用或隐藏；二选一由设计定，但不得在不可用状态放行远程资源。
    - 与 `REQ-0004` 的归属：正文打开、缓存、补拉、截断、CSP/禁 JS 仍归 `REQ-0004`/`SCN-0004`；本卡只负责开关的位置与当前邮件放行状态。`REQ-0004` 已追加 2026-11-16 澄清，不重复认领开关位置。
    - 不做「有远程资源才显示」：判断需要扫描/解析 HTML，成本与误判都不划算；开关常驻可用状态更可预期。
