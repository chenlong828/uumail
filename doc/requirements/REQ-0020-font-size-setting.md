# REQ-0020 界面与阅读字体大小可调

- **ID**：REQ-0020
- **类型**：feature
- **场景叙述**：用户从 macOS 菜单栏的「显示 > 字体大小」子菜单（与「主题」相邻）选择 100%、120%、145%、175%、225% 中一档，当前项带勾选。应用窗口内自绘文字（侧栏、列表、工具栏标签、阅读区头部、状态栏、配置页、撰写 sheet 等）与阅读区正文（作者 HTML 渲染内容）在本次操作内按该档位放大/缩小，不重开窗口、不重新加载或补拉邮件；阅读区仍白底、禁 JS 与远程资源策略不变。选择写入本地偏好，退出重开仍生效；首次运行或偏好缺失/损坏/未知时回 100%。100% 与改动前渲染一致；225% 下文字不重叠、控件不越界且均可操作。
- **价值**：不做则正文固定 13px、界面字号固定，长时间读信或视力不佳的用户只能靠系统缩放/放大镜；macOS 用户对「显示 > 字体大小」有稳定预期。应用已有主题与白底，但没有字号维度，阅读舒适度无法调整。
- **非目标**：
  - 不改字体家族；不做自定义字体、字重、字距、行距滑杆、字体导入。行距是否随档位调整由设计决定并记录，本卡不预设。
  - 不做按窗口/按邮件/按账号/按文件夹单独设置；全局一个偏好。
  - 不做「仅阅读区」「仅界面」两个独立开关；五档同时作用于界面文字与阅读正文。
  - 不做工具栏常驻字号控件、独立设置窗口/偏好面板、工具栏下拉；入口默认只在菜单。若设计认为必须新增工具栏控件，先改本卡并说明理由，不在实现里加。
  - 不做快捷键、手势缩放（⌘+/⌘-、捏合）、菜单栏图标；不做跨设备同步字号偏好、导入/导出。
  - 不改邮件内容本身，不改 MIME/发送路径，不改服务端/同步/schema/业务库；不写业务库、Keychain、网络。
  - 不改主题/白底（REQ-0015/SCN-0010）、信封头（REQ-0017/SCN-0012）、工具栏既有动作（REQ-0018/0019/SCN-0013/0014）、列表/搜索/附件/已读/删除/发送/通知的既有语义。
  - 不改 macOS 顶部系统菜单栏、窗口标题栏、系统对话框、系统文件面板、系统 tooltip；这些由系统控制，不在「界面文字」范围。字体大小菜单项本身的文字也由系统绘制，不随档位缩放。设计需在 design.md 说明覆盖清单。
  - 不新增依赖或 target，不发布 dist，不改版本号。
- **约束**：
  - 五档固定为 100/120/145/175/225（%）；100% 必须是基线恒等，不得有额外 padding/行距/字体修饰；其余档位的实际渲染字号与标称比例偏差不超过 ±8%，且随档位单调递增；100% 精确等于改动前。设计需记录实际映射与偏差；若选择动态类型近似且无法满足该容差，先改本卡再实现。
  - 必须用真实字体/排版缩放，文字保持矢量清晰；不得用 `scaleEffect` 位图放大、不得截图放大或模糊后处理；不得改变字体家族。
  - 界面文字覆盖应用窗口内自绘文本：侧栏文件夹、列表主题/发件人/日期、工具栏标签（系统允许的范围内）、阅读区头部、附件条/截断 banner/加载/失败/空态、状态栏、配置页、撰写 sheet。系统绘制的菜单栏/标题栏/对话框/文件面板不在范围；搜索框、工具栏 chrome 等系统控件按其可缩放能力处理，设计需逐项说明，不得静默漏掉。
  - 阅读正文覆盖作者 HTML 渲染内容；默认样式文本与作者显式 `px` 字号文本都应随档位缩放（机制由设计定：CSS `font-size` 注入、`WKWebView.pageZoom` 或等效方案）；表格/图片/背景不得溢出、遮挡或破坏白底；作者显式背景/颜色/字体家族保持。
  - 即时生效：选择后当前窗口与已打开邮件立即变化；不重开窗口、不重建视图树、不重新拉取/补拉正文、不触网、不重置选中/滚动/搜索/草稿。默认不得重载正文；若设计证明必须重载，先改本卡与场景卡并在 design.md 写理由与代价，不在实现里静默重载。
  - 启动时读取偏好并在首帧应用，避免先 100% 后跳变；重复选择当前档位不写偏好、不改状态、不闪烁。
  - 偏好持久化到本地 UI 偏好（`UserDefaults`），key 与 `appearance.theme` 同层（建议 `appearance.fontSize`），值用稳定 raw value；缺失/损坏/未知回 100；不写业务库/Keychain/网络；写失败不回滚当前会话、不弹错，下次启动读旧值/默认。
  - 字号偏好与主题偏好独立：切字号不改主题/白底，切主题不改字号；字号变化不得重新加载正文。
  - 225% 下（默认窗口 900×560 与放大窗口）：文字不与相邻文本/控件重叠；不出现非预期裁剪；既有 `lineLimit` 的有意省略不算回归，但所有操作入口仍可达（工具栏可进溢出菜单）；列表行、头部、状态栏不压住正文；阅读区仍可滚动，正文有可用视口；控件可点击且禁用态正确。
  - 100% 与改动前一致：界面字体使用与修饰、正文 `baseCSS`（13px/1.55）、布局边距与改动前一致；不得因新增环境值/修饰符改变基线渲染。
  - 不改 `MailDomain`/`MailStore`/`Scenes`/`MailGateway` 契约、schema、协议；字号是 UI 偏好。若新增 public 类型/成员，按 P2 提确认，本卡不代签。
  - 测试用假 HTML/假邮件，不写真实邮箱、主题、图片 URL 或凭据到日志/证据。

- 2026-11-17 设计第 2 轮（评审 fail 后回设计；无人值守默认确认，未经人工）：
  - **作用域补口**：数据库打不开时的根级错误页（`UumailApp` 中 `composition == nil` 的 `ContentUnavailableView("无法打开本地数据库"…)`）属于“应用窗口内自绘文字”，纳入本卡；不再是“系统级故障页”排除项。它走 `EmptyState`，100% 与原渲染逐点相等，>100% 标题/描述缩放。
  - **空态子树例外**：`EmptyState` 在 100% 用 `ContentUnavailableView`、>100% 用自绘分支；跨 100% 边界只切换这个**无用户状态**的占位子树，不重置选中/滚动/搜索/草稿，不构成「重建视图树」。这是本卡「不重建视图树」的显式例外，实现不得把该分支做成有状态视图。
  - **175/225% 预算**：175% 与 225% 把「头部 + 附件条 + banner」整体 cap 220pt 并内部滚动；480pt 保守可用高下正文 WebView 视口实测 259pt（≥200 下限、达 260 目标）；120%/145% 不 cap，实测 242.5/205pt（145 仍 ≥200，但不达 260 目标，设计如实记录，不用 cap 隐藏元数据来凑目标）。第 1 轮“只 cap 头部”实测 225% 视口仅 147.5pt，已否决。
  - **100% 恒等补口**：100% 只装 `\.fontSizePreference`，**不装根 `\.font`**；原来源继承默认字体的点用 `scaledInheritedFont`（100% 不加任何字体修饰）。实测装根 `.font(.body)` 会把默认两行文本从 32.0pt 压到 31.5pt；生产头部 100% 实测 159.5pt（第 1 轮 158.5pt 是 fixture/补丁副本拟合值，已更正）。
