# REQ-0012 全部回复的收件人与抄送预填

- **ID**：REQ-0012
- **类型**：feature
- **场景叙述**：用户在阅读页选中一封多人邮件点「全部回复」，撰写页的收件人自动带入原发件人与原收件人、抄送自动带入原抄送人；地址去重并排除当前账号自己，用户可直接编辑后发送。单回复与转发行为保持不变。
- **价值**：不做则群发邮件里原 Cc 的人被漏在后续沟通之外，用户每次都要手工抄地址，漏人/错人且无从核对；没有「全部回复」入口时，多人邮件只能逐个复制地址。
- **非目标**：
  - 不改单回复（现状：收件人 = 原发件人，抄送为空）；不把原 Cc 填进单回复。
  - 不做转发预填（转发收件人保持为空）。
  - 不做通讯组展开、GAL/联系人联想、收件人历史补全；通讯组/非 SMTP 地址原样保留，不解析 Exchange DN。
  - 不做「总是抄送我」、回复时改主题/引用裁剪。
  - 不改发送通道、`Outbox` 状态机、`In-Reply-To`/`References` 规则（会话头补齐另立工序）。
  - 不做多账号；只按当前账号地址排除自己。
- **约束**：
  - 必须复用 `ComposeScene` 的种子与 `Draft.cc`；视图层不得拼地址。
  - 原邮件 `To`/`Cc` 必须来自 EAS Sync 信封并随消息落库；点击回复时不触网抓头。
  - 排除自己：与当前账号 `accounts.address` 做大小写不敏感的精确地址比较。
  - 地址填充为纯地址（与现有单回复一致，不保留显示名）；拆分 `;`/`,`（引号内与尖括号内不拆），有 `<>` 取其中地址，无则整段 trim；按小写地址去重并保持首次出现顺序；多地址用 `; ` 连接；`Cc` 中与 `To` 重复的地址不再写入 `Cc`。
  - 全部回复的收件人 = 原发件人 + 原收件人（去重、排除自己）；抄送 = 原抄送人（去重、排除自己、排除已在收件人者）。
  - 头缺失/畸形时只填可解析地址，不编造；收件人为空时撰写页仍可手填，`canSend` 为 `false`。
  - 历史已同步邮件：升级后必须有一次后台回填，使最近同步窗口内的邮件具备 `Cc`；不得要求用户逐封重开或手动重同步，不得删除本地正文/附件。具体机制由设计定。
  - 实现前必须确认本网关的 Sync 信封实际返回 `Cc`；若不返回，停止并按本卡重议，不得静默退化为只填 `To`。
  - 兼容性：`Message` 只增可选字段，数据库只加可空列；旧库前滚必须有迁移测试。
- **影响场景**：
  - `SCN-0007`（已建，`verified`；验收：全部回复的收件人/抄送预填）
  - `SCN-0006`（回归：发送链路与 `Cc` 进 MIME；本卡不在其上新增断言）

  - 2026-11-14 本次为单轮需求分析，无人答问；以下结论按现有代码与标准客户端语义收敛，若与预期不符在 T-1114-01 开工前改卡。

  - 2026-11-14 范围裁决：不改单回复现状；通讯组不展开；历史邮件必须一次回填，不做逐封按需抓取。

  - 2026-11-14 设计门：`Cc` 是否由网关 Sync 信封返回仍未证；T-1114-02 未证前不实现降级。P1 核心 schema/契约需人确认后才开 change。
