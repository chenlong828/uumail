# REQ-0014 列表键盘删除

- **ID**：REQ-0014
- **类型**：feature
- **场景叙述**：焦点在邮件列表时，用户选中一封邮件按 Delete 或 Backspace：该邮件立即从当前列表消失（含搜索结果），正文区清空或切到相邻邮件；后台把它从服务器当前集合删除（按 EAS 客户端删除语义，通常进入「已删除邮件」），成功后本地行保持删除、下次同步不复活。删除失败（离线、限流、权限、设备未登记）时恢复该行与选中/正文，状态栏显示中文错误，邮件不丢，用户可重试。
- **价值**：不做则清理邮件必须去网页/手机，桌面列表只能读不能整理；键盘用户没有删除入口，企业邮箱日常整理不完整。
- **非目标**：
  - 不做多选/批量删除、撤销（Undo）、永久删除（Shift+Delete）、清空已删除邮件、滑动/右键删除。
  - 不做删除确认对话框（目标是移出当前文件夹，不是不可逆销毁）。
  - 不做离线删除队列：失败即回滚并提示，不静默保留删除意图。
  - 不清理本地正文、附件与 FTS 行；删除只让列表/搜索不再返回该行，由既有保留策略处理。
  - 不改搜索、同步窗口、通知、Outbox 与正文渲染行为。
- **约束**：
  - 删除呈现必须可回滚且与服务器一致：服务器确认前只能临时隐藏，不得落成持久删除；失败必须恢复行与选中，重启后不得残留隐藏。
  - 删除写命令与 `syncOnce` 共享同一集合游标，必须串行；不得两个网络写并发推进同一 `SyncKey`。
  - 成功时本地软删与游标推进必须一致（失败不推进游标、不留下半删状态）；同步带回同一邮件时按服务器事实处理。
  - 删除键只在邮件列表获得焦点且存在选中项时生效；焦点在搜索框、正文、撰写页或配置页时不拦截。
  - 删除后选中下一封；删最后一封选中上一封；列表为空时显示空态并清空正文。
  - 失败恢复原排序位置与选中；错误只显示在状态栏，不弹模态；同一时刻只允许一个删除在飞，连按不重复发网络。
  - 核心 `MailGateway`/`SyncStore` 契约或 schema 变更属 P1，需人工确认后才开 change；不新增 target/组件。
- **影响场景**：
  - `SCN-0009`（已建，`designed`，`design/scenarios/mail/read/keyboard-delete/scenario.md`）：新增「列表聚焦 + Delete/Backspace → 行消失、服务器删除成功、下次同步不复活、选中推进」断言；新增「服务器删除失败 → 行与选中恢复并提示」断言；新增「无选中/焦点不在列表 → 不删除」断言。这是本卡唯一验收证据。
  - `SCN-0004`（已建，`designed`）：回归删除后正文不残留上一封、相邻邮件可正常打开；本卡不新增断言。
  - `SCN-0003`（已建，`designed`）：回归删除成功后下一次增量同步不重新加入该邮件；本卡不新增断言。
- **澄清记录**：
  - 2026-11-14 首轮需求分析，无人答问；以下结论按现有代码与标准客户端语义收敛，若与预期不符由设计任务开工前改卡：
    - 键盘范围 = 列表焦点下的 Delete 与 Backspace（macOS 的 delete/backspace），不是全局快捷键；不做 `⌘⌫` 等额外组合。
    - 目标语义 = 从当前文件夹删除（EAS 客户端删除，通常移入「已删除邮件」），不是永久删除；不做确认框、不做撤销。
    - 失败语义 = 回滚 + 状态栏中文错误 + 可重试；不在离线时排队。
    - 选择推进 = 下一封优先，末条则上一封，空列表清正文与空态。
  - 2026-11-14 与 `REQ-0011`（离线可用，`draft`）的关系：删除不纳入离线意图队列；离线删除按失败处理。若要求离线可删，需先解决 `plan/open-questions.md` Q2 的 `PendingOps` 与表结构，另立工序。
