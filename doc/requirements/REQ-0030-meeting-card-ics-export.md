# REQ-0030 阅读页会议邀请卡与「在日历中打开」

- **ID**：REQ-0030
- **类型**：`feature`
- **场景叙述**：用户打开一封会议邀请邮件（如「【会议预告】AI时代的软件工程迭代和岗位变迁」），在信封头与正文之间看到一张**会议卡**：时间 `2026-11-19 09:30–12:00`、地点 `C4519`、组织者 `"王权英" <wangqy@hundsun.com>`；重复会议在卡上标注「每周一，共 N 次」之类的重复说明。点卡片上的「在日历中打开」，系统默认日历应用（Calendar.app）被唤起并导入这场会议（重复会议导入整个系列）。
- **价值**：现在邀请邮件只是一段 HTML 公告文本，用户要手抄时间地点才能排期；接入系统日历只能靠复制粘贴。会议邀请每天出现在收件箱（2026-11-13 单日一封邀请覆盖 26 位收件人），没有卡片就只能靠在正文里找「11月19日上午9:30」这类自然语言。
- **非目标**：
  - **不自动导入**：必须用户点「在日历中打开」；打开邮件不产生任何副作用、不弹系统权限。
  - 不写 Exchange 日历（无 `MeetingResponse`）、不回复邀请、不标记接受/拒绝。
  - 不改正文渲染、不改信封头行、不改远程图片与附件条。
  - 不处理「附件里的 `.ics`」：本网关的邀请邮件不把 `text/calendar` 作为附件下发（2026-11-24 实测：全库 `.ics` 附件 0 个，`ItemOperations` 要 MIME 也只回 HTML）。
  - 不集成 EventKit、不申请日历权限、不做事件去重/更新（同一会议重复导入交给日历应用自己的 UID 合并）。
- **约束**：
  - 卡片只读展示，纯本地数据（`meetings` 表），零网络。
  - 卡片只在 `Message` 带会议信息时出现；非邀请邮件无卡片、无占位。升级前已收到的邀请没有会议记录，不显示卡片（与 `REQ-0029` 的「不回填」同批确认）。
  - `.ics` 由本地会议数据生成，写到系统临时目录后交 `NSWorkspace` 打开、并按约定清理；生成失败给中文文案，不静默。
  - 时间显示按本机时区；全天事件显示为「全天」。
  - 不新增第三方依赖、不新增 target、不改 schema（复用 `REQ-0029` 的 `meetings` 表）；`.ics` 序列化在 `MailDomain`，不引入日历库。
- **影响场景**：
  - **新建 `SCN-0023`（`mail/read/meeting-card`）**：认领「邀请邮件出卡片 / 非邀请不出 / 导出并打开日历 / 畸形时区仍可读」的 3 正 1 反。
  - 回归（不新增断言）：`SCN-0012`（阅读页信封头）、`SCN-0004`（正文渲染）。
- **澄清记录**：
  - 2026-11-24 **人工确认**：动作范围 = 只读 + 「在日历中打开」，不做接受/拒绝、不调 `MeetingResponse`（与 `REQ-0029` 同批确认）。
  - 2026-11-24 **人工确认**：不回填历史邀请 → 升级前的邀请邮件不显示会议卡，卡片只对升级后新到的邀请生效。
  - 2026-11-24 默认（未经人工）：导出的是**整个重复系列**（带 `RRULE`），不是当前这一次；依据是 Outlook 同类动作导入系列，单次导入会让每周例会只出现一周。
- **状态**：`delivered`（2026-11-24 实现并验证）
- **验收归属**：`SCN-0023` 的 3 正 1 反通过 + 上述约束逐条无违反 + 回归场景不退化；需求不另立测试。
