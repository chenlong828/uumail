# REQ-0019 手动标记邮件为已读

- **ID**：REQ-0019
- **类型**：feature
- **场景叙述**：用户在邮件列表选中一封未读邮件，点击窗口主工具栏的「标记为已读」。该邮件立即在本机转为已读：列表小蓝点消失、主题字重回到常规，不等待网络；已读状态持久化，并在后台尽力回写服务器一次。已读邮件或没有选中邮件时入口不可用；服务器回写失败不回滚本地已读、不弹错误。本地写失败时邮件保持未读，并给出用户可感知的失败提示。
- **价值**：不做则用户想立刻清掉一封未读只能等自动计时，或去别的客户端操作；处理若干封需要尽快确认的邮件时没有直接入口，未读列表会长时间失真。
- **非目标**：
  - 不做「标记为未读」、全部已读、按文件夹已读、右键菜单、快捷键、批量多选。
  - 不做离线已读补写队列、跨设备一致性、已读回执、按规则/发件人自动已读；`plan/open-questions.md` Q2 的口径不变。
  - 不改自动已读的计时/取消规则（归 `REQ-0013`/`SCN-0008`）；不改删除、同步、发送、搜索、主题、通知。
  - 不做手动入口的第二套已读语义（例如直接写库或在视图里发网络）；必须复用现有本地置读 + 后台回写路径。
  - 不改 `MailDomain`/`MailStore`/`Scenes`/`MailGateway` 契约、schema、协议；不新增 `pending_op`/`readDirty` 状态；不新增依赖/target。
- **约束**：
  - 只作用于当前选中一封；本地已读先行并持久化，列表即时刷新（蓝点消失、字重常规），不等待网络。
  - 仅当本地 `isRead == false` 时触发；已读邮件重复点击/重复调用必须幂等，不产生第二次网络写。
  - 复用 `ReadScene.markReadLocally` / `writeBackMarkRead`；回写经 `SyncEngine` 与普通同步共享集合 `SyncKey` 串行门，写成功才推进 key。
  - 回写失败（offline/503/鉴权/设备未登记等）不回滚、不弹错、不重试，与 `SCN-0008` 的失败语义一致；下次同步按服务器事实更新其它邮件。
  - 本地写失败：不得把 UI 显示成已读、不得启动回写；给用户可感知的失败提示（状态栏或临时提示，由设计定），不崩溃。
  - 无选中、选中已读、选中行被临时隐藏/删除时入口不可用或动作 no-op；不得因此发网络或抛未处理错误。
  - 手动置读与自动计时同时命中时幂等：只发生一次 0→1 与一次网络写；自动计时在列表刷新后按已读取消。
  - 入口在窗口主工具栏（与回复/转发等同一组）；不新增第二条工具条/第二个已读入口。
  - 若设计需要给 `MailboxViewModel` 新增 public 方法（如 `markSelectedRead()`），按 P2 契约变更提确认，本卡不代签。
  - 测试用假邮件/假网关，不写真实邮箱、主题或凭据到日志/证据。

  - `SCN-0008`（已建，`verified`，按本批 10→3 秒修订中）：回归自动已读语义不被手动入口改坏；本卡不新增 `SCN-0008` 的断言，3 秒断言归 `REQ-0013`。
