# REQ-0029 日历页：月/周视图展示收到的会议邀请

- **ID**：REQ-0029
- **类型**：`feature`
- **场景叙述**：用户在收件箱收到会议邀请邮件——本机样本如「【会议预告】AI时代的软件工程迭代和岗位变迁」（2026-11-19 09:30–12:00，C4519，组织者王权英）、「丁丁日程」发出的「研发管理部例会」（每周一 16:00–17:00，3506）。用户打开侧栏顶部的「日历」，**月视图**里看到本月每天分布着哪些会议，**切到周视图**看到本周每天的时间轴与会议块；点某一天的会议块，看到该会议的主题、时间、地点、组织者与重复说明，并能跳回来源邮件。月/周视图都能上一周期/下一周期/回到今天。
- **价值**：不做则用户只能在收件箱里逐封翻邀请邮件，无法回答「本周三下午有没有会」「下周一和例会冲突吗」；会议邀请是本机邮箱里每天都出现的邮件类型（2026-11-13 一天内 26 人收件，钉钉日程每周固定发出例会邀请），却没有一处按时间聚合的视图。
- **非目标**：
  - **不接受/暂定/拒绝邀请**：不给组织者发任何回执，不调用 EAS `MeetingResponse`，不改变服务器上的日历或邮件状态（属后续 B 方案，另立需求）。
  - **不同步 Exchange 日历文件夹**（folder type 8）：只展示「收到的会议邀请」解出的事件；已接受后服务器日历里的预约、别人改期后的预约、自己新建的日程都不出现。
  - 不新建/编辑/删除日程；不做冲突检测、空闲/忙碌查询、会议室与资源；不做提醒与系统通知。
  - 不做日视图、日程列表视图、年视图；不做拖拽改期、缩放时间轴、打印/导出整月。
  - 不展示参与人列表与逐人答复状态。
- **约束**：
  - **只读本地库**：打开日历页、切换月/周、翻页都零网络，与阅读路径同一条不变量（`design/architecture.md` §1.3）。
  - 不新增第三方依赖、不新增 target；新场景住在既有 `Scenes` target，新组件 `CMP-SCN-CALENDAR`。
  - 时间存储一律 UTC，显示按本机时区；时区来源见下条。
  - **重复会议完整展开**：解析 EAS `Recurrence`（`Type/Interval/Until/Occurrences/DayOfWeek/DayOfMonth/WeekOfMonth/MonthOfYear`）并在可见范围展开；展开必须有界（可见范围 + 每系列上限 + 每次查询总量上限），超出给截断提示而不是卡死。
  - **同一 `UID` 只保留一封**：按 `DtStamp` 取最新；`MeetingMessageType=4`（outdated）或被取消的邀请从视图移除。
  - **历史邀请只回填一个同步窗口**：升级后首轮按现有机制重拉最近 ≤125 封（`sync_key="0"`），更早的邀请不进入日历；空态文案必须说明这一点，不假装「没有会议」。
  - 时区取 EAS `MeetingRequest/TimeZone` 的固定偏移；跨夏令时的重复展开按固定偏移计算（本机部署在 `Asia/Shanghai`，无夏令时）——该限制写入 `plan/open-questions.md`。
- **影响场景**：
  - **新建 `SCN-0024`（`calendar/browse/calendar-grid`）**：认领「月视图按天分布 / 周视图按时间轴定位 / 重复会议展开 / 空态与截断」的 3 正 1 反。
  - 回归（不新增断言）：`SCN-0003`（收件箱增量同步）、`SCN-0004`（阅读与正文补拉）。
  - 新领域 `calendar` 属业务功能树结构决定，候选与否决理由见 `history/decisions/2026-11-24-calendar-view-scope.md`。
- **澄清记录**：
  - 2026-11-24 **人工确认（三选一）**：
    1. 数据源 = **只展示收到的会议邀请**（不同步日历文件夹，也不做两期合并）；
    2. 动作范围 = **只读 + 「在日历中打开」**（不做接受/暂定/拒绝，不做本地假答复）；
    3. 重复会议 = **完整展开重复规则**（不是只显示邀请那一次，也不是只按 UID 覆盖不展开）。
  - 2026-11-24 默认（未经人工）：只清理覆盖窗口外的历史邀请、不追求「收到但正文未下载」的邀请；依据见「约束」与 `plan/risks.md` R40。
- **状态**：`accepted`（2026-11-24；场景 `SCN-0024` 已落 `designed`，实现待 P1 确认门）
- **验收归属**：`SCN-0024` 的 3 正 1 反通过 + 上述约束逐条无违反 + 回归场景不退化；需求不另立测试。
