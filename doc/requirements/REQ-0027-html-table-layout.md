# REQ-0027 HTML 正文宽表格适配阅读区

- **ID**：REQ-0027
- **类型**：`quality`
- **场景叙述**：用户打开一封正文含固定宽度表格的 HTML 邮件（Outlook/Word 生成的周报、指标表常见 `width="816"`、`style="width:612pt"`、逐列 `width`），在任意字号档位下，**页面宽度始终等于阅读区宽度**，不再出现整页横向溢出；宽表按窗宽重排列宽、文字换行，压不下去时只在**表格内部**横向滚动。右侧列不再被阅读区边缘裁掉。
- **价值**：不做则 145% 及以上字号时，本机样本的 816px 指标表把文档撑到 832px（120% 下更宽的表同样溢出），右侧列不可见且没有滚动 affordance；用户只能缩小字号或换客户端。这是「HTML 正文可读」在真实周报上的底线。
- **非目标**：
  - 不重写表格结构、不把表格转成卡片/列表、不改单元格内容与顺序。
  - 不做整页横向滚动；不改阅读区宽度与分栏。
  - 不改 CSP、不启用 JS、不改远程图片开关、不改 `baseURL`/禁 JS/白底策略。
  - 不改撰写页（`ComposeDocument` 的引言预览）的表格样式；同类问题另立。
  - 不保证无显式宽度且内容本身超宽的畸形表 100% 不溢出（见约束）。
- **约束**：
  - **CSS-only**：只改 `MessageBodyStyle.baseCSS`，不改 HTML 扫描/包裹，不新增依赖/target/schema。
  - 只命中带显式宽度的表格（`table[width]`、`table[style*="width" i]`）；无宽度表保持原表格布局，不被拉伸。
  - 页面宽度是硬约束：适配后 `document.scrollWidth == 阅读区 CSS 视口宽度`；表格内部允许 `overflow-x:auto`。
  - 图片仍受既有 `img { max-width: 100%; height: auto; }` 约束；不新增加载/下载行为。
  - 兼容字号五档（100/120/145/175/225%）与页面 `pageZoom`；不改 `MessageWebView` 的重载 guard。
- **影响场景**：
  - **新建 `SCN-0021`（`mail/read/html-table-layout`）**：认领「四档字号下页面不横向溢出 + 宽表列可达 + 窄表不被拉伸」的 3 正 1 反。
  - 回归（不新增断言）：`SCN-0004`（正文基本渲染）、`SCN-0019`（内联图）、`SCN-0010`（白底）、`SCN-0015`（字号）。
- **澄清记录**：
  - 2026-11-23 **人工确认**：表格采用「压缩适配」——列宽按窗宽重排，所有列保留，压不下去时表格内部滚动；不做「保版式 + 表内滚动」，也不做整页横向滚动。依据：本机 WKWebView 探针 668px 视口下 816px 表压到 636px，8 列全可见；120% 下保持 816px 不变。
  - 2026-11-23 默认（未经人工）：只改阅读区，不改撰写页引言；原因见非目标。
