# SCN-0027 邮件列表默认列宽

**结果**：用户打开应用或切回收件箱/发件箱时，邮件页为列表 + 阅读两栏（顶部三段切换见 `SCN-0028`）：列表默认 **480pt**、最小 320pt，阅读区取剩余宽度；窗口变窄时先压缩阅读区，列表保持 480pt 直到空间不足，且任何情况下列表不低于 320pt、不出现 0 或负宽。拖拽分栏、切换收件箱/发件箱、搜索、选中与双击打开浮窗的行为不变。

> 2026-11-24 结构变更：`REQ-0037` 去掉左侧文件夹栏，原三栏（侧栏 220 / 列表 480 / 阅读）的侧栏宽度断言随之失效；本卡按**两栏**重验，列表 320/480 口径不变。

## 入口

- `CMP-APP#MailboxView`（邮件页两栏；列表 `min 320 / ideal 480`，阅读区无显式宽、取剩余）

## 运行序

流程 `F-RECEIVE-04`：

1. 启动应用，或从日历/发件箱切回收件箱 → `MailboxView` 渲染列表 + 阅读两栏；列表取 480，阅读区不设理想宽。
2. 常见窗口（探针 1440）→ 两列实测 480 / 952；切收件箱/发件箱、搜索、选中与双击打开仍走既有路径，列宽不改变这些行为。
3. 窗口收窄 → 先压阅读区：1200 → 480/712，1000 → 480/512，900（应用最小宽）→ 480/412；继续强设到 760 → 480/272，列表仍为 480、未跌破 320 下限。

失败路径：

- 窗口极窄 → 阅读区先收缩，列表不得被压到 0 或负宽，也不得低于 320pt；若观测到任一列为 0/负值或列表 < 320，按约束违反处理。
- 列宽变化导致列表出现横向滚动条或行内换行 → 视为回归，回到设计而不是用省略号掩盖。
- 切换收件箱/发件箱、搜索时列宽被重置（跳回默认 480 或其它值）→ 视为回归，列宽应保持用户当前拖拽结果或默认 480，不因数据刷新跳变。

## 不可变引用

- `SCN-0028`：顶部三段切换与无文件夹栏；本卡只测邮件页两栏宽度，不改导航。
- `SCN-0026`：列表显示最近 30 天、不封顶与真实计数；本卡只改列宽，读取窗口不变。
- `SCN-0025`：列表行单击选中、双击/Enter/空格打开浮窗；本卡不改行手势与打开路径。
- `SCN-0009`：列表身份（folder + serverID 复合键）、删除隐藏集合与选中语义不变。
- `SCN-0024`：日历双击打开浮窗按 `(folderID, serverID)` 取单封，不依赖列表当前页；列宽不参与该读取路径。
- 不改 schema、不新增 target 与依赖；不新增列宽持久化。
