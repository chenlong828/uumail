# 首版范围与关键决策（2026-11-09）

## 背景

文档基线（`history/works/2026-11-09-doc-baseline/`）留下 8 个待拍板项和一批 `draft` 需求。2026-11-09 用问答工具逐项确认，本文件记录结论、代价与落点。冻结后作为后续工序的输入；现行设计真相仍在 `design/`。

## 决定

| ID | 决定 | 代价 / 影响 | 落点 |
|---|---|---|---|
| D1 | Provision 只做**最小握手**：维护 PolicyKey，不解析也不展示策略项 | 强制策略的服务器可能直接拒绝；错误提示须写清「本客户端不承诺策略合规」 | `CMP-EAS/spec.md`、`architecture.md` D9 |
| D2 | **单账号**首版 | 多账号延后；schema 已预留 `account_id`，扩展不改核心结构 | `architecture.md` D8 |
| D3 | DeviceId **手填**，入口放在高级设置；文档给登记/换机流程 | 首次配置多一步；客户端不承担设备登记 | `CMP-EAS/playbook.md` §6、`architecture.md` D10 |
| D4 | 发送失败件保留 **24h / 100 条**，超限提示清理 | 长期断网可能丢出发送意图；换取队列不无限堆积 | `CMP-OUT/spec.md`、`architecture.md` D11 |
| D5 | 探针抓包**脱敏后入仓**作 WBXML golden fixture；脱敏脚本与样本同目录 | 多一个脱敏脚本与一次人工检查；换 CI 可复现 | `architecture.md` §9、`plan/risks.md` R11 |
| D6 | HTML 远程资源**默认阻止、单封临时放行**；不做全局白名单 | 每封邮件需要一次显式操作；换来防追踪像素 | `architecture.md` D5、`REQ-0004` |
| D7 | 联系人 = **本机通讯录 + 收件人历史**；不暴露 GAL 入口 | 撰写补全覆盖率低于企业目录；不承诺做不到的能力 | `REQ-0001`、`plan/risks.md` R4 |
| D8 | **不做 OAuth，也不为 Graph 迁移预留抽象**：本客户端是针对私有化 Exchange 的 EAS 客户端 | 若公司迁到 Exchange Online，本项目需重新立项；换取领域契约与凭据链更简单 | `architecture.md` 变化轴、`CMP-EAS/spec.md` |
| D9 | 需求状态：REQ-0001…0007 转 `accepted`；草稿、搜索、通知、离线可用保持 `draft` | 排期只覆盖已确认范围；M3 项等 Ping/搜索验证后再签 | `requirements/` |

## 未采纳方案

| 问题 | 未采纳 | 理由 |
|---|---|---|
| 策略展示 | 完整策略展示 + 用户同意 | 首版不需要接入强制策略服务器，多一屏 UI 与状态机收益低 |
| 多账号 | 多账号进首版 | UI、Keychain、同步隔离复杂度翻倍，与首版收敛目标冲突 |
| DeviceId | IT 统一下发 / 写死受控值 | 统一下发依赖 IT 流程；写死会把设备 ID 带进代码库且换机需发版 |
| 失败件 | 7 天 / 500 条；永久保留 | 前者存储与「忘了有未发件」风险上升；后者更易误以为已发出 |
| 抓包 | 不入库 / 只入结构骨架 | 前者 CI 无法回归真实线格式；后者丢掉真实字节，回归价值打折 |
| 远程资源 | 全局阻止 / 默认加载 | 前者图片类邮件长期显示不全；后者直接暴露追踪与注入风险 |
| 联系人 | 继续排查 GAL / 只做收件人历史 | 排查无保证且推迟 M3；只做历史则补全命中率过低 |
| 认证 | 现在就设计 OAuth 设备码流程 | 当前环境用不上，属于为不存在的需求付复杂度 |
