# 风险与开放问题拍板记录（2026-11-24）

## 背景

2026-11-24 风险复核（见 `2026-11-24-risk-closeout.md`）后，对仍存在的 13 条风险与 Q1–Q7 逐项交互拍板。
分三轮：先开工前必须定的（预算、同步覆盖、浮窗图片、30 天性能、日历手势），再产品/数据口径（发件箱角标、保留策略、离线队列、进程租约、换号），
最后日历口径、即读撤销、技术欠账与发布前证据。以下为最终结论与后果；未实现部分不写成已交付。

## 一、W-M3-17 前置（先于实现）

### D1 预算：先立 P1 拆分，不上调预算

**决定**：立 P1 拆分工序，处理 2026-11-24 实测的四处超预算，再开 W-M3-17 实现：

- `Scenes` 1294/1200：拆 `HTMLText`/`InlineImageHTML` 到纯工具组件（拆分触发条件已同时满足：>1200 且已有两个 HTML 纯工具）。
- `CMP-STORE` 1152/1000：先拆 `MailStore+Meetings.swift`（273 行，设计承诺 ≤120），账号/文件夹另立 `W-REFACTOR-02`。
- `CMP-PRES` `MailboxViewModel.swift` 416/400：拆 Reader/列表窗口逻辑到新文件。
- `CMP-APP` `MailboxView.swift` 305/300：浮窗入口与手势放独立文件。

**不做**：不上调预算（1250/450/320/1400 均否决）。理由：预算门一旦为欠账让路，后续每次都会再让。

**后果**：W-M3-17 的实现任务（`T-1124-17`…`T-1124-20`）排在拆分之后；并行会话已开工的 `T-1124-17`/`T-1124-19` 需暂停或重排。
拆分后 `MailStore` 主文件与 meetings 文件的行数上限要在对应规格重写，不能沿用「约 814/924」的估算。

### D2 R21：立即修普通同步的 partial Change 覆盖

**决定**：在 W-M3-17 前修：`subject`/`sender`/`received_raw` 与 `recipients`/`cc`/`preview` 一样用 `COALESCE`，
补 L1「只带 `Read` 的 Change 不清空信封」。

**理由**：服务器只回 `Read` 的更新会把列表主题/发件人/时间清空；现有 `partialChangeKeepsRecipientsAndCc` 只覆盖 To/Cc，风险真实存在。

**后果**：`MailStore.swift#applyDelta` 与 `MailStoreTests` 小改；不新增 schema；不改写路径的「目标行保护」。

### D3 R66：浮窗远程图片维持默认显示

**决定**：维持 2026-11-24 第四轮 D6：仅浮窗阅读态默认放行远程资源，顶部静态提示；主窗口与撰写编辑器仍阻止；不扩 ATS 例外。

**代价（已知接受）**：打开浮窗即向发件人服务器发请求，追踪像素可知打开时间与 IP；同封邮件在浮窗与主窗口表现不一致。

**逆转条件**：设计评审或安全评审否决时，退回「浮窗也默认阻止 + 工具栏开关」，重开 D6 与 `SCN-0025` 断言。

### D4 R67：5k 首屏 >1s 就回设计

**决定**：`T-1124-21` 用 5,000 封夹具复跑列表 <1s；若突破，停下回设计评估分页/虚拟滚动/封顶，不静默放宽阈值、不静默改回 200。

**理由**：`REQ-0033` 明确「不封顶」，性能兜底不能由实现期私自决定。

### D5 R68：日历单击延迟 250–300ms 判定

**决定**：单击选中延迟 250–300ms 生效，双击直接打开浮窗、不再先闪一下选中。

**冲突**：并行会话的 `probe/click-catcher.txt` 显示 `clickCount=1,2` 会先发单击再发双击，并把 R68 按「立即选中」标成已关闭。
**以实现前本拍板为准**：`CalendarSelection.swift` 或等价点击捕获要加判定窗口；若实现成本过高，回设计重开 D9，不静默沿用「闪一下」。

### D6 R63：窗口载体按探针结论关闭

**决定**：接受探针结论，改用 AppKit `NSWindow` + `NSHostingController`（SwiftUI `Window` 在显示前不能可靠应用计算尺寸）。
证据 `task-spaces/20261124-152611/probe/`；真实窗口不可无头驱动的部分由 `SCN-0025` 声明 L3 + 发布前人工冒烟。

## 二、产品与数据口径

### D7 R13：发件箱角标下一批做

**决定**：W-M3-17 之后单独小批，列表/状态栏显示 `pending`/`failed` 计数；本轮不塞进浮窗批次。

**理由**：角标是独立可验收的产品增量，塞进 W-M3-17 会拖慢浮窗；但「以为已发出」的风险不能长期不处理。

### D8 Q1：本地保留 3 个月，邮件行一起删

**决定**：保留窗口 **3 个月**；超过 3 个月的邮件 **连邮件行一起删**（不是只清正文）。列表/搜索中 3 个月前的邮件直接消失。

**与旧默认的差异**：原 Q1 默认 A 是「正文保留 12 个月、信封全量」；本决定取代它。同步窗口仍是 1 个月（`FilterType=5`），3 个月是本地已有邮件的缓冲。

**后果**：

- `CMP-STORE` 清理契约要重写：删除顺序要覆盖 `messages`、`message_bodies`、FTS、附件缓存、`attachments`，以及会议行/日历引用的完整性（见 R76）。
- 搜索只覆盖 3 个月内；用户找更早邮件只能靠服务器回拉（而同步窗口只有 1 个月，实际上更早邮件不可见）。
- 删除是定期清理还是启动时清理、失败如何重试，另做设计；本轮只冻结口径。

### D9 Q2：M4 落 PendingOps 离线队列

**决定**：按 A 方案在 M4 落 `PendingOps` + 离线补写（已读/移动/删除），不在 W-M3-17 夹带。

**后果**：新增 `pending_op` 表与组件边界，需按 P1 立项；离线队列与在线写回并存的顺序/重复写/跨设备一致要单独设计（见 R75）。

### D10 Q3：M4 加进程级文件锁

**决定**：按 A 方案，M4 加 `mail.lock` + 启动检查，处理崩溃残留锁；不采用心跳列，不只靠文档约束。

**后果**：`uumailctl` 与 App 启动路径都要接锁；锁文件位置、超时与提示文案另设计。

### D11 Q4：只支持同账号重配

**决定**：只支持「同一账号重配」；换号走「清除本地数据后重配」的手动流程，需要 UI 确认框与文档。不自动删旧账号数据，不支持多账号并存。

**后果**：`AccountSetupScene.connect` 的复用行为要加前置检查；「清除本地数据」要写清删哪些表/文件（含 WAL 三件套、附件缓存、Keychain 条目）。

### D12 Q5：会议时区固定偏移

**决定**：维持只解析 `Bias` + 名称，按固定偏移展开；事件详情标注「时区按固定偏移」。不解析完整 DST 规则，不映射 IANA。

**后果**：DST 地区错一小时为已知接受；要精确另立 P2 任务。

### D13 Q6：同步 Exchange 日历集合（新范围）

**决定**：按 B 方案，后续同步日历集合（folder type 8），`meetings` 与邀请按 `UID` 去重；**不做**接受/拒绝（C 否决，避免给组织者发真实回执）。

**后果**：

- 这是新范围，不在 W-M3-17 内；另立需求/工序并做 P1（第二集合同步、合并规则、增量窗口、取消/改期冲突）。
- 与只读邀请并存时，服务器日历是权威；同一 `UID` 的邀请与日历项如何取舍、改期后旧邀请是否还显示，必须先设计（见 R74）。
- 现有「不回填历史邀请」「固定偏移」「只读邀请」的口径要重新评估，不能直接沿用。

### D14 Q7：重复会议例外继续合并

**决定**：维持现默认 A：`InstanceType=3` 的例外合并进主系列，`2/4` 与缺失按单次处理；删除例外即删该次，不回溯系列。

**后果**：`T-SCN-0024-04` 负例继续钉住；真实样本出现例外时再按实际样本调整。

### D15 R69：双击即已读不可撤销，接受

**决定**：维持 D7，不添加「标为未读」入口；误双击的未读丢失为已知接受。

**逆转条件**：用户后续要求撤销时，另立「标为未读」需求（新命令 + 服务器回写）。
