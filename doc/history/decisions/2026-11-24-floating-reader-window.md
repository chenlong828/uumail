# 浮动阅读窗与双击入口口径（2026-11-24）

## 背景

2026-11-24 需求分析（`REQ-0031` 列表双击浮动阅读窗、`REQ-0032` 日历双击打开邀请邮件、`REQ-0033` 列表默认 30 天）。
只读核对现状：

- 邮件列表是 `List(selection:)`，行上**没有双击处理**（`MailboxView.messageList`）；全 App 只有一个
  `WindowGroup("uumail")`，无第二窗口（`UumailApp`）。
- 阅读状态是单份：`selectedListKey` / `selectedMessage` / `body` / `meetingCard` 一套（`MailboxViewModel`）；
  回复种子从 `selectedMessage` + `quotableHTML` 取（`MailboxViewModel+Compose`）。
- 场景层只有按文件夹取页 `ReadScene.messages(folderID:limit:)`，**没有按引用取单封**（`ReadScene`）。
- 列表每次取 200 条（`MailboxViewModel` 硬编码），状态栏显示载入条数；同步 `FilterType=5` 即**一个月**，
  所以本地本来只有约一个月的邮件（`SyncEngine`）。
- 日历会议块是 `Button`（单击）→ 360×240 详情 sheet；详情里「打开邮件」交出 `(folderID, serverID)` 后
  主窗口切回邮件页（`CalendarView`）。
- 项目既有不变量：远程资源**默认阻止**、单封可临时放行（T5 / `SCN-0004` / `SCN-0013`）；
  已读走「列表停留 3 秒」或手动标记，服务器尽力回写（`REQ-0013`）。

用户分四轮交互确认（每轮都给了前因后果与代价，13 项口径 + 3 处推导默认）。

## 决定

### D1 拆三张需求卡

浮窗本体（列表入口 + 就地回复）、日历入口、列表默认窗口各自可独立验收；日历的真难点不是窗口，而是
「取一封不在当前列表页的邮件」；列表窗口是全局行为变更，塞进浮窗卡会让任一延迟拖住另一项。

### D2 单例浮窗

同一时刻只有一个阅读浮窗；双击另一封替换内容并置前，不新开窗口。理由：多开要每窗独立读模型与去重，
成本明显更高，而"看另一封"只需替换。代价：不能并排对照两封。

### D3 就地撰写

浮窗工具栏「回复 / 全部回复 / 转发」把内容区就地切成撰写（复用 `ComposeViewModel`/撰写视图），
取消/发送/存草稿后回阅读态。不回到主窗口 sheet，避免焦点跳窗。

### D4 工具栏只放三个动作

不加标记已读、删除、刷新、远程图片开关。理由：浮窗不持有列表状态，这些动作会把"第二窗口"
变成"第二个主窗口"。代价：删除/置读还需回主窗口。

### D5 尺寸与位置

宽 = 主窗口阅读区宽度（沿用 `REQ-0021` 口径），高 = 主窗口高度 × 85%，下限 480×460，上限不超过
主窗口所在屏幕可用高度；用户调整后记住尺寸与位置（跨启动）。

### D6 远程图片在浮窗默认显示（**改变既有隐私不变量**）

用户原话：「图片就默认显示（打开了说明很重要，需要仔细看）」。决定：

- **仅浮窗阅读态**默认放行远程资源；主窗口阅读区**仍默认阻止**并保留既有放行开关（`SCN-0013` 不变）。
- 浮窗顶部给一条**静态提示**（不阻断、不弹确认），说明图片来自发件人服务器。
- 撰写编辑器内、以及引用正文的显示**仍阻止**远程资源，避免放行状态扩散到发信路径。

代价（明示接受）：打开浮窗即向发件人服务器发请求，追踪像素能得知打开时间与 IP；同封邮件在
浮窗与主窗口表现不一致。已知 `REQ-0024` 的 ATS 例外（`NSAllowsArbitraryLoadsInWebContent`）是明文
http 图片能加载的前提，本决定不复用、也不扩大该例外。

### D7 打开浮窗即标已读

本地先落库、服务器尽力回写；本地失败给中文提示、回写失败静默不重试（沿用 `REQ-0013`）。
代价：误双击也会标已读，没有撤销。已读状态在主窗口列表同步刷新。

### D8 撰写态双击另一封不替换

只置前 + 提示「正在撰写中，请先取消或发送」。理由：替换会丢草稿（R64）；让用户自己决定何时取消。

### D9 三种打开方式等价

列表选中行：双击 / Enter / 空格都打开浮窗；日历：对选中会议块同样三者等价。理由：macOS 用户的
肌肉记忆是 Enter 打开、空格快速查看；只做双击会让键盘用户退回主窗口。

### D10 日历去掉详情 sheet

单击会议块 = 选中高亮，不再弹 360×240 详情；双击（及 Enter/空格）弹出浮窗。这是对 `REQ-0029` 已交付
行为的**显式修改**：原详情里的「打开邮件」跳转路径消失，`.ics` 导出入口迁到浮窗工具栏。

### D11 日历入口工具栏 = 转发 + 在日历中打开

用户原话：「带上转发工具栏（对日历页增加转发，意思可以转来邀请别人）」。日历入口**不带回复/全部回复**；
导出按钮承接原详情的能力；浮窗内会议卡只读、不开放按钮（避免同一窗两个同名按钮）。

### D12 按引用取单封 + 列表默认改 30 天

用户选择两条一起做：

- 新增 `MailStore.message(account:folder:serverID:)` 与 `ReadScene.message(_:)`（additive，只读，
  索引命中，跨 `CMP-STORE` / `CMP-SCN-READ` 契约，按 **P1** 单独确认）；
- 列表默认从「200 条」改为「最近 30 天、**不封顶**」，状态栏显示真实条数；搜索仍 100 条不跟随。

理由：只加宽列表覆盖不了"侧栏停在日历、列表未加载"与"其它文件夹"；只加按引用读取又留着不可解释的
200 条上限。代价：首屏读取量随邮件量增长（R67），需复跑 5k 性能基线（列表 < 1s）。

### D13 验收口径

真实窗口的默认尺寸/可移动/置前/多屏位置**无法无头驱动**，按项目惯例（`SCN-0023` 的 `NSWorkspace`、
`SCN-0013` 的替身）声明 **L3 + 发布前人工冒烟清单**；路由状态与"算出的尺寸"走 L2；不拿 L1 冒充。
窗口载体先做探针（`openWindow` 单例/尺寸/置前/取 `NSWindow.frame`），过则 SwiftUI `Window`，
不过则退回 AppKit `NSWindow`。

## 对既有文档的影响

- `SCN-0024` 的「点事件块 → 详情 → 打开邮件跳回邮件页」被替换，场景由 `verified` 转 `designed` 重验；
  这不是回归，是需求变更，须在场景卡写清替换关系。
- `SCN-0013`（远程图片默认阻止）语义**不变**，浮窗是显式例外，需在 `CMP-APP` / `CMP-PRES` 规格写清
  "例外只发生在浮窗阅读态"。
- `SCN-0004` / `SCN-0003` 的列表加载口径从「200 条」改为「最近 30 天」，属于 `REQ-0033` 的显式变更，
  不走静默改断言。
- 新增风险 R66（远程图片默认显示的隐私面）、R67（列表 30 天不封顶的性能面）、R68（日历单击/双击/键盘
  与选中态的手势冲突）、R69（双击即已读的不可撤销）。
