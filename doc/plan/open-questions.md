## Q1 本地保留策略：正文与邮件怎么裁剪

**为什么现在要问**：M1 同步大量邮件后本地库会持续膨胀（`plan/risks.md` R6），裁剪策略直接影响「搜索能不能命中旧信」和「离线能读多久」，也会改 `CMP-STORE` 的清理契约。

**选项**
- A 按时间窗口：正文保留最近 12 个月，列表信封全量保留（推荐）。代价：一年前的正文需要按需回拉，且回拉可能失败。
- B 按大小预算：库超过阈值后按最旧优先裁剪。代价：用户无法预测哪封信还能读。
- C 不裁剪：等出现性能问题再说。代价：库膨胀不可逆，M4 之前就可能卡顿。

**默认**：A，具体窗口在 M1 用真实邮箱规模校准后写进 `CMP-STORE/spec.md`。**落点**：`design/components/CMP-STORE/spec.md`。


## Q2 `PendingOps`（已读/移动/删除）何时落地

**为什么现在要问**：W-SCN-REFACTOR 只预留了端口与表位，没有 `pending_op` 表，也没有场景入口；已读回写服务器同样未实现。若继续在 UI 里直接写库，会重现本次要消除的「UI 直接写库」。

**选项**
- A 在 M3 收尾前落 `PendingOps` + `ReadScene.markRead`（推荐）。代价：多一个 L1b 组件、一张表和一轮同步语义评审。
- B 先只做本地已读标记，回写留到 M4。代价：服务器与本地已读状态分叉，换机后丢失。
- C 维持现状，不加已读/移动/删除。代价：企业邮箱基本操作缺失，M1/M3 体验目标不完整。

**默认**：A；在启动前按 P1 立项（新增组件 + 表结构），不在本工序补做。

## Q3 App 与 CLI 同库双跑的进程级账号租约是否纳入 M4

**为什么现在要问**：重构只做了 outbox 行级租约防双投；同步游标是账号级、按设备保存，两个进程同时推进同一账号的 `sync_key` 会互相顶掉（`history/works/2026-11-10-scene-refactor/result.md` 未决/遗留 5）。目前靠 CLI `--db` 默认指向 `.build/` 规避，没有强制。

**选项**
- A 进程级文件锁 `mail.lock` + 启动检查（推荐）。代价：需要处理崩溃残留锁。
- B 在 `sync_state` 上加进程/心跳列，过期可抢。代价：schema 变更、仍非强保证。
- C 不解决，只保留「不要对运行中的 App 库执行 CLI」的文档约束。代价：误操作会丢同步进度。

**默认**：C 维持现状，M4 评估 A；落点 `MailStore`（锁或 schema）与 `uumailctl` 帮助文本。

## Q4 单账号替换（改服务器/账号）的旧数据处理

**为什么现在要问**：首配后再次修改服务器或账号的行为未定义。`AccountSetupScene.connect` 会复用既有账号行并覆盖凭据，但旧账号的邮件/文件夹/sync_state 不会清理，也没有「换号」入口。

**选项**
- A 明确只支持「同一账号重配」，换号走「清除本地数据后重配」的手动流程（推荐）。代价：用户需自行清理，需给文档与确认框。
- B 换号时自动删旧账号数据（`discardAccount` 会拒绝有消息的账号，需先级联删除）。代价：不可逆，必须二次确认。
- C 支持多账号并存。代价：偏离首版单账号范围（T8）。

**默认**：A；需要 UI 与文档配合，另立工序。
